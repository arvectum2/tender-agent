## Безопасная подготовка к загрузке в Data Platform

Прочитана существующая схема Data Platform (`arvectum2/data-platform/src/arvectum_data/storage/postgres/models.py`): `dp_collections.collection_id` задаёт коллекцию; `dp_resources.resource_id` — строковый PK; уникальность ресурса обеспечивается тройкой `(collection_id, source_type, canonical_uri)`, а `external_id`, `content_hash` и JSON-`metadata` позволяют сохранять идентификаторы, происхождение и изменения контента.

Добавлен [проверяемый экспортёр](../../scripts/market_intelligence/export_pq_data_platform.py), преобразующий v8 (58+2=60) в **60 строк JSONL для будущего staged import**, без подключения к БД. Предлагаемая коллекция — `arvectum-market-pq-6-35kv`; источниковый тип `market_intelligence_procurement_research`. `resource_id` и `canonical_uri` детерминированно основаны на SHA-256 `canonical_id`, поэтому повторное обнаружение той же закупки не создаст новый логический ID. `content_hash` строится из канонически сериализованной исходной карточки. В метаданных сохраняются URL, слои доказательств, `date_basis`, класс оборудования, тип суммы и статус официального договора. По умолчанию экспорт только печатает JSONL; **производственного импорта, INSERT/UPDATE и доступа к PostgreSQL здесь нет**.

[Регрессионный тест экспорта](../../tests/test_mi013_pq_data_platform_export.py) проверяет 60 уникальных идентификаторов, детерминированность хеширования, наличие ссылок, отсутствие вымышленных поставщиков и сохранение `deadline_date` при неизвестной дате публикации. Перед фактическим импортом необходимо реализовать проверку доступа к целевой коллекции, dry-run сравнения 60 строк с фактическим состоянием PostgreSQL, транзакционное применение и read-back; работа с БД в этом исследовательском проходе **не выполнялась**.

## Проход 9: обнаружена реально работающая промышленная Data Platform и подготовлен импорт

27.10.2026 в read-only режиме через Arvectum Remote Cloud проверено `docs/RUNTIME_MACMINI.md` репозитория `arvectum2/data-platform` и фактический runtime. Старое предположение, что работающая БД Data Platform ещё не развёрнута, **опровергнуто**: Data Platform слушает `127.0.0.1:8094` (HTTP health 200, `environment=production`), launchd `com.arvectum.data-platform` работает. Каноническая база платформы **`arvectum_data`**, а не `arvectum`; обе находятся внутри существующего Docker PostgreSQL `arvectum-postgres` с pgvector.

Из реальной БД прочитаны 26 коллекций, 2192 ресурса, 2192 документа, 0 структурированных `dp_records`; все таблицы `dp_collections`, `dp_resources`, `dp_records` присутствуют. Целевая коллекция исследования `arvectum-market-pq-6-35kv` пока не существует (`SELECT EXISTS` вернул false), существующих её ресурсов **0**. Значит, **новая БД/таблицы/миграции не нужны**. Предыдущие отрицательные проверки выполнялись в базе Tender Agent `arvectum`, поэтому вывод о «неразвёрнутой Data Platform» был ошибочным.

Подготовлен [production-safe SQL importer](../../scripts/market_intelligence/import_pq_postgres_v12.py) с предсказуемым целевым набором ровно **71 source-linked lot-level карточка** v12. Каждая карточка добавляется двумя связанными объектами: `dp_resources` (canonical ID SHA256, контрольная сумма, оригинальные URL и evidence tier) и `dp_records` (`pq_procurement_notice_lot`, первичный структурированный JSON и статус `unreviewed`). При повторном запуске `resource_id` сохраняется, по идентичному контенту revisions не меняются; изменившиеся записи обновляются. Контроль транзакции запрещает коллизии с другими коллекциями, неполный импорт откатывается, доступ ограничен отдельной коллекцией `tender-agent`.

Режим по умолчанию — **dry-run без любых SQL/системных эффектов**; `--check-db` дополнительно выполняет только read-only запросы. Производственный `--apply` требует точного разрешения владельца на команду, указания правильной БД, создания резервной копии через уже штатный `scripts/ops/backup-postgres.sh` c SHA256 manifest, а после транзакции проверяет обе таблицы по 71 строке. [Проверки](../../tests/test_mi013_pq_postgres_import_v12.py) контролируют отказ по умолчанию, целевую БД, стабильные ключи и защитные барьеры. [Операционный runbook](MI013_PQ_POSTGRES_IMPORT_RUNBOOK.md) содержит точные команды.

**На момент записи этого раздела сама производственная загрузка ещё НЕ выполнена.** Требуется отдельно одобрить изменяющую данные команду ARC, а также доставить ветку исследования в отдельный worktree на Mac mini (существующий checkout Tender Agent на `feature/apr07-quality-slo-evidence` содержит четыре изменённых tracked-файла, их нельзя затрагивать). CI последнего HEAD ожидает выполнения.

Даже после транзакции это будет **структурированное хранение** 71 карточки в `dp_records`, а не уже готовые 71 векторизованных документа. Для полнотекстового/семантического поиска нужен отдельный шаг штатного ingestion в `dp_documents`, `dp_chunks`, `dp_chunk_embeddings` с проверяемыми источниками.
