# Tender Agent: извлечение квалификационных критериев из оригинального файла ЕИС

**Проверено на ЦЗН Московской области №0348100024426000039, редакция ЕИС №4 (13.10.2026).**

До этого этапа компонент референс-листа PR407 корректно сравнивал список выполненных договоров с *предоставленным* структурированным `QualificationCriterion`. Источник цифровых весов оставался потенциальной точкой ручной ошибки. Теперь отдельный `qualification_original_source.py` **вычисляет их по оригинальным бинарным файлам**. Продукт не подставляет значение 70/30 по номеру закупки.

## Доказательная цепочка

1. В закрытом каталоге Mac mini на ArvectumSSD находится оригинальный архив, полученный официальным `getDocsIP`: `documentation-archive.zip` 76 759 байт, SHA-256 `dad574a4bd996a675645bdf538ed13201cc59983417d2c153467bb3f9d2d4908`. Архив включает оригинальные редакции извещения 1–4 и XML разъяснений.
2. Сначала проверяется **полный SHA-256 всего архивного ZIP** против ранее сохранённой доверенной квитанции, отсутствие опасных записей/DTD и актуальная максимальная редакция извещения. Для редакции №4 проверяется XML SHA-256 `bd6a4261995882d42dfe37d3809a26c722ea771d782e5bac6be4b76675d5fb6c`, тип `epNotificationEOK2020`, номер извещения, `endDT` и точный URL/UID документа из первичного архива.
3. Для исходного файла «Порядок рассмотрения и оценки заявок» проверяется `publishedContentId=01A0F10655C27A35B5A5A70090D2BB1A`, размер **22 427 байт** и SHA-256 `bda1eff35bffda97f5a8e661f5d9fd5d221562e2b00e55feec28cb3fbd745dd8`. Файл расположен исключительно в закрытом хранилище Mac mini, копий исходного бинарника в GitHub нет.
4. Без запуска Office/Microsoft Word, макросов или LLM читаются **структурные таблицы DOCX** через ZIP/XML. Из колонки «Значимость критерия оценки» единственной таблицы извлекаются:
   - Цена контракта — **30%**.
   - Квалификация — **70%**.
5. Из строки `4.1.1` самой документации извлекаются критерий **«Общее количество исполненных участником закупки договоров»**, допускаемые **44-ФЗ/223-ФЗ**, работы с **чат-ботом**, необходимость подписанного последнего акта не ранее **5 лет** до окончания подачи и исключение незавершённых договоров. Из `endDT` актуального оригинального XML получается календарная дата **23.10.2026** в МСК.
6. Лишь после этих проверок данные передаются в уже существующий детерминированный `assess_references()` PR407. Подтверждённый владельцем референс-лист «Арвектума» на 13.10.2026 пуст, поэтому итог — **`NO_GO_QUALIFICATION_COMPETITIVENESS`**, `qualifying_contracts=0`. Юридический допуск, вероятность победы, подтверждённая цифровая подпись и `human_gold` от этого не возникают.

## Воспроизведение на Mac mini

```bash
cd /Volumes/ArvectumSSD/Arvectum/runtime/ta-qualification-original-source-20261013
/Users/master/arvectum-runtime/tender-agent/.venv/bin/python \
  -m scripts.acceptance.replay_qualification_scoring \
  --archive /Volumes/ArvectumSSD/Arvectum/runtime/ta-apr06-czn-v4-eis-official-20261013/documentation-archive.zip \
  --scoring-docx /Volumes/ArvectumSSD/Arvectum/runtime/ta-apr06-czn-v4-eis-official-20261013/source-files-v4/current-v4-scoring-original.docx \
  --receipt docs/acceptance/apr06_czn_v4_official_scoring_source_receipt_2026-10-13.json \
  --owner-input docs/acceptance/arvectum_owner_reference_list_and_czn_2026-10-13.json \
  --as-of 2026-10-13
```

Сценарий **только читает** файлы и печатает JSON, не обращается в сеть, не меняет БД, не запускает модель, не подаёт заявку и не включает SaaS. Исторический `owner-input` содержит сделанное пользователем заявление «нет исполненных контрактов», а не криптографически подписанный реестровый факт.

## Принципы fail-closed

| Несовпадение | Действие |
|---|---|
| SHA-256 SOAP архива или исходного DOCX | Ошибка, прекращение расчёта |
| Оригинальная редакция XML не совпадает с квитанцией или содержит более позднюю редакцию | Ошибка, нельзя применять старую оценку |
| Нет текущего UID документа / не сходится длина | Ошибка |
| Формат таблицы неоднозначен, есть дополнительные критерии, неверная сумма весов или дробные веса | Ошибка, **ручная оценка**, никакого автоматического 70/30 |
| Нет явных подтверждений чат-бота, законов 44/223, пятилетнего срока и исключения незавершённых договоров | Ошибка |
| Вредоносный ZIP, DTD XML, макрос/бинарный DOCX | Ошибка |
| Нет подтверждённого референс-листа компании | `QUALIFICATION_EVIDENCE_UNKNOWN`, а не ноль |
| Только оценка 70/30, но юридический допуск не исследован | Только отдельное коммерческое `NO_GO`; запрет на заявку не выводится |

**Ограничение:** валидатор проверяет хешированные оригиналы и их согласованность с ранее зафиксированной официальной цепочкой, **но не валидирует криптографическую подпись ЕИС**. Не следует рекламировать `source binding` как полноценную проверку электронной подписи.

**Следующий интеграционный этап:** после подтверждённого оригинального документального источника агент должен автоматически найти документ оценки в EIS-run workspace, извлечь критерий и вывести персонализированное заключение пользователю через SaaS/API и в итоговом отчёте. В этом PR есть переиспользуемый детерминированный parser + подтверждённый реальный replay, но он пока не выполняется автоматически при каждом запуске общего `analyze_uploaded_demo_run`. Подмена исходных данных из HTTP-запроса пользователем не должна заменять доверенный источник.
