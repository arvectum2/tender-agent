# Tender Agent — автоматическая квалификационная оценка в отчёте SaaS

**Дата:** 13.10.2026. **Статус:** инженерный read-only пилот, stacked draft PR над оригинальным источником ЕИС (PR #408) и референс-листом компании (PR #407). Не является релизом или коммерческой приёмкой.

## Как теперь работает штатный путь

1. Авторизованный пользователь компании с ролью owner/admin/analyst открывает пилот SaaS и запускает **«Скачать документацию ЕИС в мой контур»**. Существующий `POST /api/saas/runs/from-eis` вызывает штатный `getDocsIP`, сохраняет ZIP и догружает вложения из XML текущей редакции. `SaasRun` фиксирует **tenant_id**: чужой идентификатор run не даёт доступа.
2. **В момент получения** оригинального архива агент сохраняет `archive_stored_name` + `original_getdocs_archive_sha256` в metadata прогона; штатный downloader добавляет `source_download_sha256` к каждому локально сохранённому вложению. Это **внутренняя квитанция транспортных байтов**, а не электронная подпись. Для прежних прогонов без квитанции автоматический скоринг **недоступен** — нужен повторный импорт ЕИС, не догадка или подставленный хеш.
3. На просмотре **«Посмотреть отчёт»** существующий `GET /api/saas/runs/{run_id}/report` проверяет Bearer-токен, принятие условий и владение прогоном, затем **автоматически** добавляет отдельный объект `qualification`. Отдельный `GET /api/saas/runs/{run_id}/qualification` позволяет получить то же до завершения LLM-анализа. Никаких весов, UID, SHA или `customer_id` передавать в запросе не нужно.
4. `qualification_run_service.py` сам находит транспортно удостоверенный ZIP из каталога **только своего прогона**, проверяет хеш времени скачивания, считывает оригинальное извещение `epNotificationEOK2020` с максимальной редакцией и находит единственный подходящий DOCX по актуальным `publishedContentId` + имени + размеру + разрешённому HTTPS URL + SHA от времени загрузки. Если таких файлов нет или их несколько — **`NOT_ASSESSED`**, не вымышленное решение.
5. `qualification_original_source.py` читает таблицы DOCX и извлекает веса критериев и определение зачётных контрактов. `qualification_references.py` читает из версии хранилища профиля **именно этой компании** её завершённые договоры. Конкурентный вывод не подменяет существующий `decision.status` (правовой/документальный).
6. Клиентский интерфейс `/saas` содержит кнопку **«Оценить шансы по оригинальным критериям ЕИС»** и отдельную видимую панель с вердиктом, количеством квалифицирующих контрактов, весами цены/опыта и предупреждением об ограничениях источника. Значения в DOM устанавливаются **только через textContent**, без вставки HTML из источников.

**Доступ:** owner/admin/analyst могут получать оценку. Участник `viewer` по-прежнему может просматривать разрешённый существующий отчёт, но его `qualification` содержит только `REFERENCE_ACCESS_RESTRICTED`, **без сведений из приватного референс-листа**. Чужие прогоны блокируются проверкой `owned_run` ещё до чтения вложений.

## Границы доверия и дальнейшие действия

- **Цифровая подпись оригинального извещения ЕИС НЕ проверена.** Подтверждены HTTPS-источник, связь XML/UID/содержимого, SHA-256 при получении и неизменность локальных байтов. Это нельзя выдавать за юридически заверенную достоверность извещения.
- **Неизвестный/просроченный/неполный референс-лист** даёт `HUMAN_REVIEW_REQUIRED`, не `NO_GO`. Для ООО «Арвектум» владелец сообщил об отсутствии завершённых контрактов 13.10.2026; при первой завершённой закупке требуется записать новую версию референс-листа и подтвердить акты.
- **Неподходящий закон, неразобранный DOCX, отсутствие оригиналов или неоднозначный критерий** приводят к `NOT_ASSESSED`; агент не переносит 70/30 из ЦЗН на другие тендеры.
- Для извлечения нового документа ЕИС штатная сеть остаётся с **прямым HTTPS/no_proxy и российским IP** по действующей настройке. Этот этап не менял PAC, системный proxy, конфигурацию сети или токены.
- Анализ делается **при запросе отчёта**, а не фоновым наблюдением. Нет автоматической подачи заявки, изменения цены, оплаты, подписания, продакшен-развёртывания или обновления watchdog.
- SaaS остаётся выключен до отдельного решения о включении. Привязка собственного действующего `customer_id` «Арвектума» и ввод пустого референс-листа в **рабочую** базу не выполнены: не следует угадывать tenant или делать скрытую запись.
- Подтверждение независимым человеком (human-gold APR-06), окончательная юридическая оценка, владельческие KPI и APR-07 production SLO остаются **отдельными незакрытыми воротами**.

### Следующий продуктовый этап

Расширить извлечение критериев на другие поддерживаемые форматы и условия конкурсов (223-ФЗ, PDF/табличные документы оценки, сложные составные критерии), но только через явные проверяемые parser contracts и реальные первичные источники. Не заменять `NOT_ASSESSED` уверенной оценкой LLM. Подготовить интерфейс референс-листа для обновления завершённых договоров с актами, затем проверить интеграцию на нескольких реальных разных закупках; сохранить коммерческие решения за владельцем.
