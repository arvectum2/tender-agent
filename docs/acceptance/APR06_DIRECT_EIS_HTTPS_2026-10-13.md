# APR-06 — прямой HTTPS к ЕИС: диагностика нестабильного HTTP 404 (13.10.2026)

**Результат: воспроизведён непостоянный ответ публичных узлов ЕИС.** Пользователь открыл официальную ссылку ЦЗН через Chromium GOST с российского IP. Независимая проверка на Mac mini той же ссылки **без прокси** получила и `200`, и `404`. Закупка остаётся на этапе подачи заявок: действующая редакция извещения **№ 4**, срок **23.10.2026 10:00 МСК**. Редакция № 3 от 08.10 с дедлайном 19.10 устарела.

## 1. Фактический маршрут подключения

- Mac mini: PAC macOS `http://127.0.0.1:8082/proxy.pac` включён; внутри PAC `zakupki.gov.ru` отнесён к `DIRECT`, остальные сайты обычно идут через `PROXY 127.0.0.1:8080`.
- В окружении терминального процесса отсутствуют `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`. Для проверки дополнительно использовались `curl -q --noproxy '*' --proxy ''`; это гарантирует отсутствие прокси **для данного процесса**, но не меняет систему или пользовательский браузер.
- Независимая проверка геолокации внешнего IP дала **RU, Moscow**, AS25513. Сам внешний IP в Git не сохранялся.
- Публичная официальная главная страница `https://zakupki.gov.ru/epz/main/public/home.html` и карточка Музея хлеба ответили `200`; HTTP `404` от голого корня `https://zakupki.gov.ru/` не относится к состоянию конкретных закупок.
- В имеющемся коде `src/shared/network/http_client.py` `create_urllib_opener(...,source_direct_connection=True)` уже использует `ProxyHandler({})`, то есть не наследует прокси для публичных EIS-ресурсов.

## 2. Причина первоначального ложного HTTP 404

Официальный URL:

`https://zakupki.gov.ru/epz/order/notice/ok20/view/common-info.html?regNumber=0348100024426000039`

Восемь повторных **GET** к **тому же HTTPS URL**, с одного российского IP, с `--http1.1` и `--noproxy '*'`:

| HTTP | Количество | Возвращённый `Via` |
|---|---:|---|
| `200` | **6** | `eis-varnish-pub02.zakupki.local (Varnish/7.7)` |
| `404` | **2** | `eis-varnish-pub01.zakupki.local (Varnish/7.7)` |

`200`: официальный HTML «Сведения закупки», около 204 КБ. `404`: nginx HTML-заглушка **146 байт**. Обоими ответами служил `zakupki.gov.ru`, сетевой адрес **95.167.245.92**; признаков смены прокси при этих запросах нет.

**Вывод:** нестабильность узлов кеша/обработчиков ЕИС — сильное объяснение наблюдаемого поведения. Фактически подтверждена корреляция `pub01→404`, `pub02→200` в этом эксперименте, а не вся внутренняя причина неисправности у оператора ЕИС. Нельзя считать единичный 404 доказательством отмены или завершения закупки. После одного успешного ответа удалось получить также вкладки `documents.html` и `event-journal.html` с HTTP 200.

По данным HTML ещё не подтверждены свежие байты всех четырёх вложений и хеш оригинального XML редакции № 4.

Недостающий ZIP редакции № 3 был пропущен при первоначальном скачивании с `HTTP 429`. Сейчас он уже устаревшая редакция: восстановление только этого старого ZIP не закроет документы действующего извещения. В первую очередь нужны четыре новых вложения редакции № 4 по официальным UID и её оригинальный XML с корректной provenance.

## 4. Исправление Tender Agent

В текущем [PR #404](https://github.com/arvectum2/tender-agent/pull/404) улучшен `Public44FzSearchProvider._fetch_page`:

- **Только** HTTPS страницы `zakupki.gov.ru/epz/order/notice/<method>/view/{common-info,documents,event-journal}.html`, ровно один 19-значный `regNumber`;
- повторное чтение возможно **только** при HTTP `404`, заголовке `Via: eis-varnish-pubNN.zakupki.local` и узнаваемой короткой HTML-заглушке `nginx 404`;
- максимум **две дополнительные попытки** с паузами 0,25 и 0,5 секунды; повторные запросы — только GET, без изменения домена и прокси;
- HTTP `403`, `429`, обычные `404`, другие домены, неуспешные TLS/капча — **не повторяются** этой логикой; при постоянном `404` выдаётся ошибка получения источника, **не решение о статусе закупки**;
- успешный ответ сохраняет количество EIS-cache retries в диагностике `detail.raw`, где это предусмотрено.
- Дополнительно закрыта небезопасная проверка хоста по простому окончанию строки: допустим лишь сам `zakupki.gov.ru` или корректный поддомен, а не `fakezakupki.gov.ru`.

Это точечное исправление, не изменение общего HTTP-клиента, авторизации, ETP, ставок либо production.

## 5. Границы экспертной оценки

Подтверждены текущая **HTML-редакция № 4**, этап, срок и перечень официальных UID на момент запроса. Но не подтверждены оригинальный архив XML № 4, его SHA-256, полный набор байтов новых вложений, пригодность ТЗ и независимые человеческие коммерческие оценки. APR-06 остаётся **не принятым**.

Никаких заявок, подписей, платежей, внешних писем или развёртываний не производилось. Настройки PAC/прокси не изменялись.
