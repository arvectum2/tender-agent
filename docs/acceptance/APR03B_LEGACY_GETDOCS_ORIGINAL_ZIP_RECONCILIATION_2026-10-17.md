# APR-03B — восстановление связи старого запуска с исходным ZIP ЕИС

**Единственный интерфейс:** существующий Mac mini Operator Workspace на 127.0.0.1:18082. Никаких новых UI, баз, стендов или повторных скачиваний.

## Сведения, доказанные первым просмотром без изменений

- Исторический run Музея хлеба toa-run-20261012200402-7249ed / номер 44-ФЗ 0372200172326000015 уже имеет 6 документов, ранее сверенных по SHA-256 с authenticated HTTP downloads.
- В input этого же run уже присутствует documentation-archive.zip: 17041 байт, SHA256 35978ce41fc87955491cc53705b0bd126c6d8217b82134e640eed1d78ed9e500.
- Исторические журналируемые события getDocsByReestrNumber, eis_archive_url_received, eis_archive_downloaded однозначно указывают на официальный host int.zakupki.gov.ru, имя документа и тот же размер 17041. Это привязка к сохранённому GET/POST receipt, не проверка цифровой подписи ZIP.
- Независимый классификатор исходного ZIP: ATTESTED_COMPETITIVE, epNotificationEZK2020, запрос котировок 44-ФЗ, highest **archived** version 1; внутри ZIP только один XML epNotificationEZK2020_0372200172326000015_1_01A11A810BFD7EBAB3819B3AE3BE0014.xml, 102910 байт, SHA256 ed5c742b554913c65d9001b658aa23619df418b2d19e6f6d6754a1bc70141bba, полностью совпадающий с ранее проверенным FILE-01.
- Оставшиеся **5 вложений** (XLS/DOC/DOCX/PDF) находятся вне этого ZIP. Нельзя утверждать, что они присутствуют в этом архиве или получили тем самым подтверждение своего официального происхождения.
- В старом metadata поля archive_stored_name, original_getdocs_archive_sha256, official_eis_procedure и notice_revision_selected были пусты; это ошибка сохранения привязки, а не отсутствие исходного ZIP.

## Реализация

Скрипт scripts/ops/reconcile_legacy_getdocs_archive.py по умолчанию только читает прежний run. Проверяет единственность SOAP download-event и размер ZIP, SHA-256, классификацию, точное соответствие source XML и сохранённого FILE-01. При конфликте выполняет fail-closed; запись разрешена только с explicit --apply и обеими ожидаемыми SHA-256 (старой metadata и ZIP), после отдельного backup. Поле archived_zip_reconciliation явно помечает: ретроспективная проверка сохранённого архива, а НЕ SHA в момент первоначального транспорта.

Существующий модуль operator_workspace_evidence.py будет показывать pinned_latest_archived_notice_revision для единственной проверенной архивной версии, как и для нескольких, с предупреждением, что **live current EIS revision NOT verified**. Архивная PDF/DOCX выдача должна оставаться HTTP409, автоматический business GO запрещён.

## Не снятые ограничения

Невозможно из этого сохранённого ZIP доказать актуальность официальной публикации на 17 октября, официальный transport-time archive SHA/подпись, полный состав пяти внешних вложений, юридическую/экономическую оценку или owner GO. Дополнительная независимая официальная ревизия и подтверждение владельца требуются отдельно.
