# ArvectumSSD: восстановление чтения и миграция данных R4

**15.10.2026.** Во время предыдущего запуска внешнее USB/APFS-хранилище ArvectumSSD оставалось смонтированным, однако чтение git metadata и .agent checkpoint надолго зависало. Работа продолжалась только во временном Git checkout на внутреннем SSD Mac mini с точным HEAD удалённой PR #432; приватные первоисточники были резервно сохранены на внутреннем диске.

## Фактическая проверка

При текущем запуске чтение тех же git metadata, обоих YAML checkpoint и предыдущего private holdout-lock успешно восстановилось, без перезагрузки Mac mini. Команда проверки тома macOS `diskutil verifyVolume` запустила `fsck_apfs -n -l -x` на смонтированном томе и завершилась с **exit code 0**, проверив superblock, object map, snapshots, fsroot, extent map и container allocation. Том и контейнер APFS признаны исправными.

SMART через используемый USB-контроллер недоступен; по одному успешному `fsck` невозможно подтвердить исправность USB-моста, кабеля или отсутствие кратковременных зависаний ввода-вывода. Значения sleep и disksleep Mac mini уже равны 0; дополнительных системных настроек не меняли. Не выполнялись принудительное размонтирование, перезагрузка или ремонт с записью на диск.

## Результат миграции

- Код действующей ветки R4 на ArvectumSSD fast-forward до GitHub HEAD, исходный worktree чист и все проверенные контрольные файлы по SHA совпали с временным checkout.
- **31 приватный файл** (4 HTML-захват/квитанции и 27 EIS ZIP/21 оригинал/квитанции) мигрирован из временного хранилища, повторно прочитан непосредственно с ArvectumSSD и проверен SHA-256. Из них 21 официальный бинарный оригинал, остальные — оригинальные EIS ZIP, HTML и технические квитанции.
- Прочитан и подтверждён первоначальный private blind-lock 3/16; четыре новых кейса и все 21 оригинал не пересекаются с 20 историческими и тремя старыми blind-закупками.
- Создан неизменяемый второй partial blind-lock (4/12) и четыре приватных evaluator-пакета с пустыми независимыми формами; никакие документы или токены не помещены в Git.

Применимый статус: **SSD работает и актуальные данные находятся на нём; причина предшествовавшей USB-паузы не доказана**. При повторении проблемы необходимо сохранить журнал ядра и USB, проверить кабель/порт/USB-мост и провести контроль состояния диска через диагностический инструмент, способный читать SMART за USB.

Внешние ограничения по Tender Agent сохраняются: из требуемых 12 новых закупок получены четыре, независимая юридическая разметка ещё не создана, SUT на blind-выборке не запускался, bid_ready=false.

## Проверка после переноса

Полная регрессия выполнялась непосредственно на ArvectumSSD с подключёнными приватными источниками: **4 250 passed, 242 skipped, 0 failed, 329 warnings, 150.06 секунды**. Три приватных QA-журнала сохранены на SSD, каждый сверён с оригиналом. Внешний SSD продолжил отвечать на чтение и запись.
