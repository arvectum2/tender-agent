# APR-06 — проверка сохранённых редакций ЕИС и сопоставление вложений (13.10.2026)

**Статус: автономный аудит локального архива — выполнен. Полнота действующей документации и юридическая приёмка — НЕ ПОДТВЕРЖДЕНЫ.** Аудит проведён исключительно по ранее сохранённым исходным байтам, без сети, без новой загрузки из ЕИС, без доступа к ЭТП. Подробные результаты: [JSON на 20 кейсов](apr06_archived_notice_binding_2026-10-13.json).

## Методика и границы

1. Для каждого `run_id` из [исходного журнала SHA-256 09.10](apr06_real_probe_receipts_2026-10-09.json) считываются `procurement/attachments_manifest.json` и только исходные `input`-файлы, уже покрытые SHA-256 и размером из этого журнала. Произвольные документы из каталога не повышают статус.
2. Из XML `epNotification*` извлекаются исходный реестровый номер, числовая редакция `versionNumber`, официальная `commonInfo.href`, дата окончания подачи `endDT` и объявленный комплект `attachmentsInfo`. Отдельные события `epClarificationDoc`, отмена заявки и другие не-извещения **не становятся редакциями**. Неверный номер/хост, совпадающие номера редакций, расхождения байтов и неоднозначность обрабатываются с отказом от подтверждения.
3. Из последней **сохранённой** редакции берутся **имя, размер, `publishedContentId` (UID) и HTTPS URL** каждого вложения. Эти поля сопоставляются с исходным архивным `attachments_manifest.json`: его `source_url` содержит `uid`, а фактические байты файла должны совпасть с исходным журналом SHA-256. Несовпадение имени, размера, UID, домена или хеша блокирует положительную корреляцию. Дубликаты и неявные приведения имени запрещены.
4. **Важное ограничение:** найденное архивное соответствие `XML.publishedContentId` ↔ `manifest.source_url.uid` ↔ исходные хешированные байты подтверждает именно **сохранённую** цепочку источника. Это более сильное доказательство, чем совпадение имени и размера. Но действующая онлайн-редакция ЕИС и неизменность опубликованных сейчас UID **не проверены**. Также не проверены полный официальный комплект, закупочные правила, коммерческая применимость и человеческая экспертная оценка.

### Подтверждённая причина одного конкретного пропуска

В ЦЗН МО `0348100024426000039` присутствует сохранённый XML редакции 3 со сроком 19.10.2026 10:00 МСК, а в его `attachmentsInfo` содержится семь вложений. Шесть имеются в локальном архиве с совпадающими именами и размерами, для седьмого документно-процессинговый журнал показывает: `status=skipped`, `http_status:429`. Пропущен архивный файл **«Приложение к проекту контракта, сост. 08.10.2026.zip»**; размер по XML **499 446 байт**.

Это доказанный **сбой загрузки/ограничение частоты при первоначальном скачивании**, но не доказательство отсутствия исходного документа у заказчика. Требуется контролируемая повторная *read-only* загрузка только данного `publishedContentId` / официальной ссылки после проверки актуальной редакции, с ограниченным retry/backoff и проверкой ZIP-сигнатуры. До получения байтов и верификации соответствия конкретной редакции — `docs_required`.

## Техническая воспроизводимость

Код: `scripts/acceptance/apr06_archived_notice_binding.py`, регрессии: `tests/test_apr06_archived_notice_binding.py`. Тесты включают устаревшую редакцию, отсутствующее вложение, неизвестный дедлайн, поддельный реестровый номер, иной домен, дубли редакций, недостоверную SHA, XML не-извещения и попытки выхода за исходную директорию.

Запуск производится **без сети** в отдельном контейнере с `--network none --read-only`, с архивами `:ro`, а диагностический JSON создаётся в новом локальном файле. Исходные байты, подписи, токены и персональные данные в Git не выгружаются. Внешние заявки, письма заказчикам, платежи и подписи не выполнялись.

**Итог:** 50 из 77 вложений последних сохранённых редакций связаны с локальными оригиналами по четырём признакам: исходный реестровый XML, `publishedContentId`/UID из официального URL, точные имя и размер, SHA-256 исходных байтов. Это проверенная **архивная** корреляция, не подтверждение действующей онлайн-версии. Остальные 27 отсутствуют или не подтверждены локально; коммерческая приёмка и current-EIS source checks остаются открытыми.
