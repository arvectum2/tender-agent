## Происхождение

Таблица воспроизводимо собрана из метаданных, находящихся **в отдельной, не слитой в main ветке** `feature/apr07-quality-slo-evidence` репозитория `arvectum2/tender-agent`, зафиксированной для этого экспорта на SHA `fc41e652b64ea27bda0f96a4b2e5f5967e87374e`. Источник поступил в ту ветку через commit `891b6fe0`. Это **не** канонический утверждённый корпус основной ветки.

Исходные машиночитаемые записи:

- `docs/acceptance/apr06_real_probe_receipts_2026-10-09.json` — 20 закупок 44-ФЗ, 168 записей файлов с SHA-256, из них 17 с отдельным хешем извещения. По источнику 9 закупок получили технический результат анализа, 11 — `docs_required`.

Скрипт выполняет только локальную валидацию и детерминированный экспорт. Он **не** запрашивает ЕИС, не перечитывает файлы за пределами переданных JSON, не проверяет фактические байты и не вызывает LLM.

## Воспроизведение

Из checkout, где доступны оба указанных JSON-файла, или с абсолютными путями к сохранённым входным файлам:

```bash
python scripts/acceptance/build_apr06_human_review_queue.py \
  --receipts /authorized/path/apr06_real_probe_receipts_2026-10-09.json \
  --machine-audit /authorized/path/apr06_independent_gpt6_audit_2026-10-09.json \
  --out docs/acceptance/TDP_R5_20_CASE_HUMAN_REVIEW_QUEUE_2026-10-11.csv \
  --expected-cases 20
```

Ожидаемый контрольный итог: `cases=20 files=168 hashed=168 human_signed=0 source_validation=not_done`. Результат не включает внутренние `run_id`, локальные пути, содержимое документов, секреты и персональные данные проверяющих.

## Что делает независимый проверяющий

1. По публичному реестровому номеру определить **актуальную на момент проверки** редакцию на официальном ЕИС, дату публикации, статус процедуры, а также основания отмены/изменений. Зафиксировать URL, номер редакции и дату проверки в защищённой ведомости.
2. Независимо получить и сверить оригинальные бинарные файлы, их SHA-256, комплектность технического задания, проекта договора и иных обязательных документов, сопоставить resource/document/chunk и точные цитаты, учитывая расхождения содержимого архивов.
3. Проверить предмет, сроки, НМЦК, риски, экономику, отсутствие необоснованных числовых утверждений и источники каждого существенного вывода агента. Для неустановленного оставлять `UNKNOWN`.
4. Принять по каждой закупке атрибутированное решение `GO / NO_GO / DEFER` с объяснением, датой и подписью/ссылкой на отдельный защищённый протокол. Не записывать персональные данные и приватные источники в этот публичный CSV.
5. Подготовить итоговые 20 независимо проверенных кейсов для согласования порогов качества R4/R5 и отдельного подтверждения владельцем продукта. Без этого `.agent/current-task.yaml` сохраняет `in_progress`.

Колонка `machine_revision_mismatch_flag` — только сигнал из другой модели, **не** подтверждение неверной или действующей редакции. `source_receipt_operator_reviewed=false` и `source_receipt_revision_human_verified=false` отражают исходный снимок, не текущее состояние работы оператора. Поля человеческой проверки умышленно пустые и не изменяются автоматически при повторном экспорте.
