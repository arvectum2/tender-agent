# APR-06 — пакет независимой человеческой проверки, 13 октября 2026

**Приватная подготовка интерфейса — выполнена. Коммерческая приёмка — НЕ ВЫПОЛНЕНА.**

Генератор `scripts/acceptance/apr06_review_packet.py` автономно формирует
только локальную HTML-очередь из двух уже существующих, явно неполных источников:
`apr06_candidate_pool_2026-10-09.json` и `apr06_machine_prefill_2026-10-09.json`.
Он **не делает сетевых запросов**, не создаёт экспертных мнений, не получает
сведений о действующей редакции ЕИС и не записывает решений в БД или на ЭТП.

В приватной директории Mac mini создан файл:

`/Users/master/arvectum-runtime/private-operator-acceptance/apr06-review-queue-20261013.html`

Права 0600. Доступ к девяти отчётам — через защищённый локальный Operator
Workspace на `127.0.0.1:18083`, который запросит обычную авторизацию при
необходимости. Список с персональными отметками проверяющего публично не
публикуется. При обновлении файла генератор требует новый путь: существующий
результат не перезаписывается.

Запуск для новой датированной версии:

```sh
python -m scripts.acceptance.apr06_review_packet \
  --manifest docs/acceptance/apr06_candidate_pool_2026-10-09.json \
  --prefill docs/acceptance/apr06_machine_prefill_2026-10-09.json \
  --output /Users/master/arvectum-runtime/private-operator-acceptance/apr06-review-queue-NEW.html
```

**Фактический состав:** 28 кандидатов, 9 машинных отчётов, 20 кейсов с
неполным/неподтверждённым текстовым комплектом (19 вообще без отчёта, один
имеет 10 извлечённых файлов из 19). Ни одного документально удостоверенного
reviewer ID, подтверждённого хеша текущего комплекта или человеческого
GO/NO_GO/DEFER не создаётся.

Для каждой закупки оператор отдельно проверяет существование и подлинность
извещения, актуальную редакцию, вложения, обязательные требования и цитаты,
после чего фиксирует реальные время работы, evidence refs и экспертное решение
по `docs/acceptance/APR06_PROTOCOL.md`. Если данных недостаточно —
`DEFER`. Сводка **не предназначена** для автоматической подачи заявок,
принятия решения о допуске или демонстрации принятой коммерческой точности.

Проверки:

  приватные ссылки, XSS и подделанные run_id, повторную запись, отсутствие
  искусственного human-review, отклонение любых не-loopback URL.
- Полная регрессия с PostgreSQL 16 / Docker — записать отдельно после прогона.
- Требуются живой эксперт и утверждённые собственником пороги APR-06.
