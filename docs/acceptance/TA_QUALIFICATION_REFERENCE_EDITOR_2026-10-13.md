# Tender Agent: референс-лист компании — безопасный редактор в SaaS

**Дата:** 13.10.2026. **Статус:** локальная инженерная функциональность в stacked draft PR поверх PR409/408/407. Не является публичным развёртыванием.

## Что получил пользователь

В существующем локальном кабинете `/saas` в блоке **«3a. Референс-лист исполненных контрактов»** добавлены:

- **«Загрузить мой референс-лист»**: читает только `GET /api/saas/qualification/references`, показывает `UNKNOWN` для отсутствующей записи, текущий `fact_version`, заявленную полноту, дату и имеющиеся договоры. Никакая форма не приравнивает отсутствие списка к подтверждённому нулю.
- **«Добавить договор»**: создаёт поля для 44-ФЗ/223-ФЗ, номера, типа проекта (сайт/портал/ИС/модуль), признака чат-бота, признака полного исполнения, даты последнего подписанного акта и ссылок на исходный договор и итоговый акт. Для незавершённых договоров ссылки на акт не обязательны, но незавершённые **не засчитываются** как квалификационный опыт.
- **«Сохранить новую версию»**: требует даты подтверждения и основания `source_ref`. Полный список (`COMPLETE`) нельзя сохранить без явного checkbox подтверждения владельца; частичный (`PARTIAL`) не доказывает ноль. Отправляет только собственную информацию авторизованного Bearer-пользователя, не запрашивает `customer_id` и не открывает внутренний API профиля.
- Все поля добавляются безопасно через `document.createElement`, значения серверных данных выводятся через `value`/`textContent`, никаких `innerHTML` для пользовательских ссылок/названий договоров.

## Версионность, права и параллельные правки

`POST /api/saas/qualification/references` теперь требует **`expected_version`**: пользователь сначала читает текущую запись (`null` превращается в `0`), затем сохраняет следующую версию. Если другой владелец или администратор успел сохранить изменения, API возвращает **HTTP 409** с требованием перечитать список, а не молча перезаписывает их. При одновременном race уникальность версий в БД дополнительно защищает от двух записей одного номера; ошибка `IntegrityError` перехватывается как `409` и откатывает транзакцию.

`owner/admin` могут сохранять, `analyst` — читать, `viewer` не получает частный референс-лист. Существующие tenant-scoped API сохраняют проверку принятия правовых условий. История старых версий остаётся в таблице `CompanyProfileFactVersion`, новую запись нельзя превращать в автоматическую независимую `human gold` или `legal eligibility`.

**Изменение контракта API:** поле `expected_version` **обязательно** для новых записей. Обновлены тестовые клиенты. Внешним клиентам SaaS-пилота при будущем включении потребуется сначала выполнить GET, затем передавать полученную версию в POST.

## Результат для ООО «Арвектум»

На 13 октября 2026 г. владелец подтвердил отсутствие исполненных контрактов. Через этот редактор такой факт можно внести как `COMPLETE`, `contracts: []`, с датой и явным подтверждением владельца. **В этом PR рабочая база данных не изменялась** и пользовательский SaaS не включался.

Когда первый договор будет **реально исполнен** и акт подписан, владелец может добавить договор, указать ссылки на источники, сохранить новую версию, и следующий оригинальный source-bound отчёт Tender Agent сможет пересчитать квалификацию. Наличие ссылки на акт — это заявленные пользователем данные, **не криптографическая проверка документа**; независимая экспертиза и проверка конкурса остаются отдельными.
