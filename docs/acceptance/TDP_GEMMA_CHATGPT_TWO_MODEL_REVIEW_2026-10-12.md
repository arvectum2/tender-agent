# R4/R5: локальная Gemma исполняет, ChatGPT независимо проверяет — 2026-10-12

**Объём:** десять закупок, по которым в исходном локальном архиве Tender Agent доступны нормализованные документы с контрактными условиями; 20 архивных дел рассмотрены отдельно в [сводной матрице](TDP_CHATGPT_20_CASE_SOURCE_SCREENING_2026-10-12.md).

## Реально выполненный эксперимент

- **Исполнитель:** локальная `arvectum-gemma4-12b-it-qat-q4_0` на Mac mini, loopback HTTP `127.0.0.1:8081`. Никакие оригиналы не отправлялись во внешнюю LLM.
- **Вход:** 23 независимо найденных ChatGPT/локальной проверкой исходных фрагмента в 10 делах, строго с именами файлов и смещениями нормализованного текста. Исходные байты из read-only локальной копии 52 контейнерных прогонов, рабочий Docker и production не изменены.
- **Задача Gemma:** без GO/NO_GO выделить буквальную цитату и узкое утверждение о сроках, обеспечении, оплате, стеке, правах. Только источник, предоставленный в фрагменте.
- **Результат:** 10/10 вызовов `evaluated` за суммарные **131.37 с**; **26** заявленных выводов, **25/26** цитат буквально совпали с переданными соответствующими фрагментами, **1/26** не совпала. **9/10** кейсов имели буквальное совпадение всех цитат модели.
- **Независимый буквальный oracle:** `source-anchor-verification-20261012.json`, **23/23 проверочных фрагмента** исходного нормализованного текста, 10 дел, SHA256 текста + символьный offset. Это другая проверка, не оценка качества смысловой интерпретации.
- **Исходные приватные протоколы на Mac mini:** `evidence/tdp-r5/ai-expert-20261012/gemma_contract_second_opinion_private.json`, `source-anchor-verification-20261012.json`, `case-review-packets-private.json`. Не публиковать текст оригиналов и приватные реквизиты.

**Сводка:** exact-literal accuracy модели **25/26**, семантическое превышение уверенности как минимум в **1** утверждении при точной цитате. Поэтому **буквальная цитата сама по себе не доказывает правильность юридической интерпретации**. Результаты со статусом `SOURCE_CLAIM` — сведения из фрагментов, а не лицензированная правовая экспертиза полного пакета или допуск к участию.

## Решение экспертного контура

**AI independent screening пройден по 20/20 делам в пределах имеющихся материалов**: 10 source-rich, 7 archive-only, 3 `no_data`. Source-rich не означает полную приёмку каждого приложения. Ни одно из 20 дел не получило достоверно подтверждённых актуального опубликованного статуса, комплексной оценки соответствия требованиям и расчёта коммерческой экономики, необходимых для автоматического GO.

**Следовательно, финальное безопасное решение второго контура — `DEFER / manual_review_required` по всем 20**, а не коммерческое NO_GO. Все 20/20 реальных подписей/разрешений владельца по-прежнему отсутствуют. Технический staged DP→Tender Agent E2E пройден отдельно: источники 5/5, чанки 127/127, анализ/report HTTP200, архивный canonical PDF/DOCX fail-closed HTTP409.

## Правило готовности для продукта

Для любого `GO` одновременно необходимы: matching registry ID, актуальная редакция/статус официального ЕИС, все существенные первоисточники с точными локаторами и смысловой проверкой, расчёт экономики, ограничения участия, договор/обеспечения и явное решение владельца. Ошибка хотя бы в одном обязательном поле → `UNKNOWN` / `DEFER`, а не «вывод вероятно верен». Не подписывать заявки, не изменять production, не обходить экспортный HTTP409.

Рекомендуемые последующие работы: принять этот AI reviewer-gate как внутренний контроль качества, сделать машинный exact quote check обязательным и хранить различающиеся оценки `QUOTE_MATCH` и `SEMANTIC_REVIEW`; дополнить Golden Dataset материалами с настоящими ошибками исходных версий, а не только синтетическими кейсами.
