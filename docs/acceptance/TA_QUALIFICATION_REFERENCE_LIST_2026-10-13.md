# Qualification reference list: источник фактов, а не предположение агента

**Арвектум, 13.10.2026:** владелец в диалоге сообщил, что ООО «Арвектум» пока не имеет ни одного **исполненного** контракта. Для конкурса ЦЗН МО `0348100024426000039` по действующей редакции EIS **№4** число зачитываемых контрактов равно 0, а опыт составляет **70%** оценки, цена — **30%**. **Коммерческий вывод: `NO_GO_QUALIFICATION_COMPETITIVENESS`**. Он не означает запрета на подачу заявки.

Исходное утверждение владельца не является подписанным актом/внешней проверкой. Оно явно хранится как `CUSTOMER_PROVIDED`, поэтому не превращается в независимый `human gold`.

## Канонический источник

Для каждого **customer_id** продукт читает последнюю неизменяемую `CompanyProfileFactVersion` с ключом `completed_contract_reference_list` и группой `EXPERIENCE`. Это существующая версия хранилища компании, не общий демонстрационный профиль. Чтобы зафиксировать первое подтверждённое состояние:

```http
POST /api/company-profile/customers/{customer_id}/facts/completed_contract_reference_list/versions
Content-Type: application/json

{
  "fact_group": "EXPERIENCE",
  "value": {
    "schema_version": "completed-contract-references-v1",
    "as_of_date": "2026-10-13",
    "completeness": "COMPLETE",
    "owner_confirmed": true,
    "contracts": []
  },
  "source_type": "CUSTOMER_PROVIDED",
  "source_ref": "OWNER_USER_STATEMENT_2026-10-13_ZERO_COMPLETED_CONTRACTS"
}
```

**Важно:** эту запись нужно создавать в базе **соответствующего customer_id** ООО «Арвектум»; не присваивать любой другой компании и не создавать `customer_id` по догадке. В PR есть машиночитаемый пример [owner input](arvectum_owner_reference_list_and_czn_2026-10-13.json); он не означает, что запись уже внесена в рабочую БД.

При появлении исполненного контракта добавляется новая версия через тот же маршрут (`version_no + 1`), а не редактируется предыдущая. Каждый договор указывается с законом 44-ФЗ/223-ФЗ, предметом, `chatbot_in_scope`, `completed`, `acceptance_signed_at`, ссылкой на договор и подписанный итоговый акт. Незавершённый договор можно учесть в референс-листе, но он **не начисляет баллы за выполненный опыт**.

## Проверка по конкретному извещению

```http
POST /api/company-profile/customers/{customer_id}/qualification/assess
Content-Type: application/json
```

Тело — поле `czn_source_bound_criterion` из [owner input](arvectum_owner_reference_list_and_czn_2026-10-13.json), в котором закреплены номер закупки, версия EIS, UID + SHA-256 исходного документа оценки, веса критериев, виды допускаемого опыта и дата анализа.

Сервис возвращает `QUALIFICATION_EVIDENCE_UNKNOWN`, если факт отсутствует или его источник не `CUSTOMER_PROVIDED`/`OWNER_CONFIRMED`; `QUALIFICATION_EVIDENCE_EXPIRED` если текущая версия просрочена; `QUALIFICATION_EVIDENCE_PARTIAL` если список неполный; **`NO_GO_QUALIFICATION_COMPETITIVENESS`** при подтверждённом нуле договоров и преобладающем весе квалификации (инженерное правило данного MVP: не менее 60%); `QUALIFYING_REFERENCES_PRESENT_REVIEW_SCORE` если есть потенциально зачётные контракты.

Этот результат **не** подтверждает юридическую допустимость, не вычисляет точную вероятность победы и не разрешает подачу заявки. При смене редакции извещения нужно извлечь, подтвердить и заново связать критерий с актуальным документом. **Перенос цифр 70/30 на другие конкурсы запрещён.**

## Интеграция и остающиеся ограничения

Детерминированный модуль `src/modules/company_profile_store/qualification_references.py` работает с версионным профилем и доступен по read-only маршруту оценки. Он не использует общий демо-профиль, не обращается к ETP, не меняет статус закупки и не вызывает платные модели.

До сквозного внедрения в каждый автоматически создаваемый отчёт Decision Core требуется контролируемая передача `customer_id` исполнителя и подтверждённого, текущего критерия оценки из оригинального извещения. В отсутствие этих двух связей итог **UNKNOWN**, а не ложное `NO_GO`. Такая интеграция — следующий самостоятельный этап, её нельзя выдавать за уже реализованную.

Тесты защищают отсутствие списка, неполный список, разные компании, устаревшие версии, незавершённые договоры и контракты без чат-бота, сроки акта, правильный закон и исходный UID/SHA критерия. Дополнительный детальный разбор ЦЗН: [PR #405](https://github.com/arvectum2/tender-agent/pull/405).
