# Tender Agent — выбор оригинального DOCX/PDF в SaaS-отчёте компании

**13.10.2026.** Инженерный read-only этап после PR409 (tenant-bound report), PR413 (исходный PDF 44-ФЗ). Не является боевым запуском.

## Изменение штатного сценария

Авторизованный пользователь с ролью owner/admin/analyst запрашивает `GET /api/saas/runs/{run_id}/report` или `GET /api/saas/runs/{run_id}/qualification`. Прежние проверки `owned_run`, `principal.customer_id` и согласия с условиями сохраняются, а роль viewer не видит частного референс-листа.

При формировании `qualification` агент:

1. Сначала применяет **существующий** строгий DOCX-путь: только оригинальный `getDocsIP` PRIZ 44-ФЗ, последний исходный XML, UID/name/size/официальный HTTPS и SHA-256, полученный **при скачивании**. При соответствии известной методике и подтверждённому owner-профилю он сохраняет прежнюю квалификационную оценку (пример — ЦЗН).
2. **Только если однозначно не найден поддерживаемый DOCX-порядок оценки**, агент рассматривает отдельные PDF. Для каждого PDF обязательно: исходный run metadata из того же проверенного каталога, официальный `notice/attachmentInfo` текущей редакции, SHA-256 исходного SOAP-архива **от времени загрузки**, UID, точное имя, размер, URL, SHA-256 сохранённого при загрузке PDF. Подмена оригинального DOCX не разрешает обходную PDF-ветку.
3. Через `pdftotext -layout` только локально и с ограничениями времени/объёма агент пытается применить **узкий** документно подтверждённый наблюдатель составной 44-ФЗ методики. Если критерии противоречивы, PDF недоступен, вариантов более одного или вложение повреждено — остаётся `NOT_ASSESSED`. Нет поиска по имени закупки, подстановки процентов и внешнего OCR/LLM.
4. При подтверждении исходного PDF структура `criterion_source` получает **`price_weight_percent`, `qualification_weight_percent`, `qualification_subweights_percent`**, а отдельный `source_status` сообщает о транспортной связности оригинала, **не** о проверенной электронной подписи. `competitive_recommendation=NOT_ASSESSED`, `qualifying_contracts=null`, `human_gold=false`, `legal_eligibility_assessed=false`, `external_action_allowed=false`.
5. В SaaS-панели `NOT_ASSESSED` теперь отличает *«оригинальный документ найден, нужны специалисты и опыт»* от *«источник не подтверждён»*. Данные выводятся через `textContent` без опасного HTML.

Оригинальный PDF и ZIP конкурса 1С находятся в отдельном защищённом каталоге Mac mini. **Они не импортированы в производственную SaaS-БД**. Реальный исходный PDF ранее отдельно прошёл offline replay исходной процедуры PR413. Новая маршрутизация проверена синтетическим полностью source-bound run fixture и существующими тестами SaaS/ЦЗН; это **не** заявляется как состоявшийся боевой SaaS-прогон на реальных данных.

## Проверка и ограничения

Изолированный Mac mini checkout `/Volumes/ArvectumSSD/Arvectum/runtime/ta-qualification-multiformat-run-routing-20261013`.

На коде `7c33710` локально завершено **96 pytest PASS**, Ruff PASS и `git diff --check` PASS. Среди тестов:
- DOCX-маршрут ЦЗН остаётся неизменным, в частности проверка подмены оригинала;
- PDF-путь только при отсутствии подходящего DOCX, замена на разные/дублирующиеся PDF → `NOT_ASSESSED`;
- старые прогоны без download-time digest, подменённый PDF, неверный режим 223-ФЗ, чужой HTTPS-host не попадают в доверенный отчёт;
- без проверки специалистов и без отсылки к числу выполненных договоров не выставляется `NO_GO`;
- остаётся прежняя SaaS-аутентификация и разграничение данных по клиентам.

Следующий шаг: расширить библиотеку действительно оригинальных DOCX/PDF разных процедур с source receipts и отрицательными тестами, подготовить проверяемый критерий специалистов; отдельно согласовать коммерческие пороги с владельцем. **223-ФЗ** имеет иную структуру XML `purchaseNotice` и оригинальные RAR/PDF; его наблюдатель PR412 **ещё не подключён** к автоматическому PRIZ-роутингу.
