# R4/R5 и ARV-001 — машинная подготовка независимой экспертной проверки

**Задача:** `TA-EXPERT-SOURCE-PACKET-20261014`, стадия 3 работы над качеством исследования закупочной документации. Техническая ветка поверх source proof PR #427 и full-corpus PR #426. Черновик, никакого слияния/production/ЭТП.

## Принцип

У Tender Agent **уже есть** `docs/acceptance/TDP_R4_R5_HUMAN_GOLD_PROTOCOL_2026-10-12.md` с 20 исходными закупками и `docs/quality/ARV-001_Golden_Report_Quality_Gate.md` с существующими критериями доказательности. Повторный критерий приёмки не создаём. Машинный анализ формирует **предзаполнение**, а не решение эксперта.

`expert_source_review_packet.py` формирует отдельный JSON блок `expert_source_review_prefill` в trace/requirements, не меняя замороженный R3-оркестратор. Пакет содержит:
- номер закупки только из однозначного оригинального XML ЕИС (иначе `null`);
- детерминированный SHA-256 манифеста документов и реестр `file_id` / роли / `text_sha256` / `raw_sha256` / статуса принятия, с обязательным отображением отсутствующих или отклонённых файлов;
- **16 категорий рубрики** из существующего R4/R5: актуальная редакция, заказчик/предмет, целостность, количества, ТЗ, допуск, лицензии, срок подачи, НМЦК/изменение цены, обеспечение, поставка/приёмка, ответственность, оплата, права, гарантия, критерии оценки;
- источнико-адресные кандидаты для рассмотрения и перечень только тех ссылок, для которых есть exact normalized quote+SHA proof. Наличие фрагмента не подтверждает смысл;
- конфликты source-modality и исходных чисел/дат, недостаток извлечений, необнаруженные темы/изменённые редакции;
- **пустые** `human_label`, `human_reviewer_id`, `human_reviewed_at`, `human_evidence_note` по каждой категории. Разрешённые будущие ручные статусы `VERIFIED / UNKNOWN / CONFLICT / NOT_APPLICABLE`.

**Независимые запреты:** `human_reviews_completed=0`, `human_gold_attested=false`, `current_official_revision_attested=false`, `expert_signature_present=false`, `arv001_release_gate=NOT_READY`, `bid_ready=false`. Эти поля **не** вычисляются из количества найденных цитат или прохождения JSON-схемы.

## Реальный read-only replay Музея хлеба

Сохранённая архивная закупка `0372200172326000015`: 6/6 исходных нормализованных текстов проиндексированы, 15/15 выбранных фрагментов проверены по точным диапазонам и SHA. Пакет содержит 6 исходных документов, **16 категорий рубрики**, 15 проверенных ссылок на нормализованный исходный текст, а не на придуманные страницы PDF.

Исходный ответ local Gemma4 с source-v2 prompts ранее правильно указал архивные НМЦК и срок, но назвал обязательное ограничение «только СМП/СОНКО» предпочтением. Независимый source-modality audit передал в пакет **1 противоречие**; `human_reviews_completed=0`, `ARV-001=NOT_READY`, `bid_ready=false`.

Это машинный baseline для эксперта, **не** human-gold validation. Не подтверждены актуальная редакция ЕИС, право Арвектума на участие, юридическая квалификация условий и подпись владельца. В существующем протоколе 20 закупок и **0/20 человеческих подписанных оценок**.

## Отдельные следующие этапы

1. Удостоверенное Data Platform отображение страниц PDF/листов и ячеек XLSX по исходным байтам (нынешний source-span — только смещение нормализованного текста).
2. Полный атомарный semantic entailment verifier со строгим `UNKNOWN` для неподтверждённых толкований и редакций; нельзя считать LLM-перефразирование доказательством.
3. Подготовка исходных материалов для независимых экспертов по **существующим 20 R4 кейсам**, потом их реальные `VERIFIED / UNKNOWN / CONFLICT / NOT_APPLICABLE`, заметки, время, две независимые проверки и согласованный ARV-001 gate. До получения подтверждений не утверждать точность или `GO`.

Никакие оригинальные документы закупки, приватные ответы LLM или персональные данные не публикуются на GitHub; в репозитории хранятся только исходный код, тесты и этот агрегированный отчёт.
