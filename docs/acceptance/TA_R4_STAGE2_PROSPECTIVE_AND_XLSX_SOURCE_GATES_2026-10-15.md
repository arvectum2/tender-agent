# Tender Agent R4: вторая blind-выборка и проверка Excel-цитат

Состояние на 15.10.2026: **протокол отбора второй когорты зафиксирован; новых подтверждённых кейсов во второй когорте пока нет.** Три ранее выбранных EIS-кейса и 16 исходных вложений остаются закрытыми для SUT; независимые квалифицированные gold-подписи отсутствуют.

## Дополнительное исключение утечек

Ранее 20 конкурентных исходных извещений и 96 оригинальных вложений используются как development-корпус. Теперь к запрету повторного отбора добавляется **предыдущая, отдельно зафиксированная слепая когорта 3/3 и её 16 оригинальных SHA**. Функция forbid_reuse_of_prior_blind_cohorts проверяет неизменяемость каждого раннего lock, пересечения по номеру, ZIP XML и исходным бинарным файлам, и отказывает при повторном включении. На Mac mini проверено: защищено 23 уникальных номера и 112 уникальных исходных SHA.

## Что именно предварительно зарегистрировано

Независимый source-only план:
docs/acceptance/data/TA_R4_STAGE2_PROSPECTIVE_SOURCE_SELECTION_INTENT_2026-10-15.json

- Цель: **12 новых** подлинных конкурентных ИТ-закупок 44-ФЗ, без гарантии набора при недоступных источниках.
- Порядок обнаружения: два заранее заданных публичных каталога Tendigo (разработка ПО, затем разработка сайтов), только видимые строки в исходном порядке rank. Ровно первая подходящая закупка с новым номером, без содержательного просмотра ТЗ; фильтрация 223-ФЗ и уже использованных номеров; дубликаты между каталогами исключаются.
- Исходный каталог — **только источник идентификаторов**, не подтверждение действительности закупки, конкурса, договора или момента приёма заявок.
- До рассмотрения в качестве реального кейса требуется independently trusted официальный getDocsIP, конкуретный тип XML и SHA/размер каждого бинарного оригинала ЕИС. Иначе этот номер не засчитывается.
- Ни результаты Tender Agent, ни отчёты о «простоте» закупки не участвуют в выборе. Все отклонения фиксируются; недостаток доступных строк = UNDERFILLED, а не произвольная замена более удобными извещениями.
- Время регистрации намеренно предшествует новым пригодным снимкам страниц. Старые кешированные страницы или ошибки 404 не допускаются.
- Любая смена источников, квоты или правил должна стать **новым протоколом/новой когортой**, а не скрытой правкой существующего.

Код общего отбора: r4_prospective_sampling.py, проверенный входной адаптер: scripts/acceptance/select_r4_prospective_source_candidates.py. После получения действительного нового снимка каталогов он создаёт лишь **private DISCOVERY_ONLY** номера. Следующие ступени официальной верификации сохраняются в prepare_r4_unseen_semantic_holdout.py с обязательной проверкой ранних lock-файлов.

## Текущий объективный блокер нового набора

Публичный поиск ЕИС по HTML ранее давал unsupported_layout; legacy SOAP поискового метода с настроенным токеном сейчас вернул HTTP 404. Попытка получить свежую страницу каталога прямым HTTPS и альтернативным средством чтения также завершилась без пригодного нового источника. Имеющийся проиндексированный публичный каталог указывал обновление от 14 октября; он **старше регистрации** новой когорты. Поэтому **0 дополнительных case manifests, 0 новых оригиналов и 0 новых юридических gold**. Само наличие 12 запланированных мест нельзя преподносить как 12 найденных закупок.

## Excel: проверка конкретной исходной ячейки

r4_original_text_extract.py теперь принимает ограниченные по размеру **статические ячейки XLSX**, создавая локаторы SHEET-<имя листа> CELL-<ячейка>. Вход — исходный SHA-проверенный бинарный файл; xlsx открыт только для чтения, формулы не вычисляются, ошибки и формулы запрещены для автоматического цитирования. Составной ZIP с единственным XLSX тоже допускается. r4_external_gold_intake.py требует, чтобы дословная цитата действительно присутствовала **в указанной ячейке**, а не просто в другом месте файла. Ранее реализован аналогичный барьер для конкретного абзаца/ячейки таблицы DOCX.

Этот метод не анализирует автоматически изображения, диаграммы, формулы Excel, сканированные PDF, встроенные объекты или правовое значение условий. Извлечение текста отдельной ячейки **не доказывает полноту чтения всей закупочной документации**. Такие материалы блокируют автоматическую фиксацию неподтверждённых цитат и требуют квалифицированной ручной сверки. Тесты XLSX используют только искусственные книги; 16 оригиналов blind-когорты не передавались анализатору.

**Итог:** новая когорта зарегистрирована как намерение, не сформирована; прежние три blind-кейса нетронуты; human gold 0/3; семантическая precision/recall НЕ измерялась; bid_ready=false.
