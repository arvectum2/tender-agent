# Tender Agent — проверка исходных цитат и критических утверждений, этап 2

**Задача:** `TA-SOURCE-CLAIM-PROOF-20261014`. Ветка `feature/source-claim-proof-20261014`, draft-PR поверх PR #426 (исследование всего корпуса). Эта стадия не является юридической приёмкой или разрешением на подачу заявок.

## Разрыв, устранённый после полнотекстового индекса

Даже при полнотекстовом индексе модель может (а) назвать чужой диапазон оригинальной цитатой, (б) назвать архивную цену и срок неверно или умолчать о них, (в) приписать нормализованному тексту PDF-страницу, которой экстрактор не устанавливал. Успешная JSON-схема не решает ни одну из этих проблем.

### Исходный доказательный фрагмент

`source_claim_proof.bind_source_span` проверяет одним контрактом:
- наличие принятого `EXTRACTED` файла из реестра индекса, уникальный `file_id` без учётного регистра и его `SHA-256` по всему нормализованному UTF-8 тексту;
- соответствие оригинальным данным `[char_start:char_end]` (включая кириллицу и юникод), точный текст цитаты и её SHA-256;
- если документ ранее отклонён из-за отсутствующего/ошибочного declared SHA или дублирования ID, повторно использовать его как доказательство **запрещено**;
- локаторы «страница PDF», «страница DOCX», «ячейка XLS/XLSX» **не выводятся из количества символов**. Если нет отдельно подтверждаемой карты координат, состояние `PAGE_OR_CELL_NOT_ATTESTED`, а не вымышленный номер; даже явно представленное соответствие остаётся `EXPLICIT_SOURCE_MAPPING_REVIEW`, а не семантическим заверением.

Символьный диапазон относится к нормализованному тексту, **не** к страницам исходного PDF или координатам таблиц; `semantic_verification=NOT_PERFORMED`.

### Независимая проверка структурированных цен и сроков

`check_typed_original_facts` получает `structured_notice_facts` только от защищённого парсера оригинального XML ЕИС из PR #426 и сравнивает **типизированные значения** `nmck`, `submission_deadline` и `procurement_subject`, а не просто совпадение отдельных слов.

Результаты разделены:
- `MATCHES_HISTORICAL_EIS_SOURCE` — значение подтверждается **только сохранённой исторической редакцией XML**, не статусом LIVE.
- `CONTRADICTED_BY_HISTORICAL_EIS_SOURCE` — числовое/временное значение не совпадает с данным исходным XML.
- `SOURCE_CORPUS_OR_REVISION_UNRESOLVED` и `CONFLICTING_SOURCE_VALUES` — неполный корпус, несколько извещений/изменений или противоречивые оригиналы.
- `UNKNOWN_NOT_ATTESTED` — источник не содержит такого типизированного поля, декларация неверного типа, например B2B/223-ФЗ не является XML ЕИС 44-ФЗ.

`extract_model_eis_summary_claims` допускает только **явно подписанные** НМЦК/NMCK и срок подачи/Submission deadline из ответа модели; непонятное число в прозе не назначается НМЦК. `audit_model_eis_summary` отдельно отмечает `unmentioned_archived_eis_fields` и число противоречий. Проекция Tender Agent добавляет поля `source_eis_typed_claims` и `source_quote_proofs` в существующие trace/requirements, а `source_research_quality_gate` переводит ложную цену или срок в `CONTRADICTION_REVIEW_REQUIRED`. В любом случае `bid_ready=false`, `current_official_revision_attested=false`, `semantic_entailment_verified=false`.

## Что ещё НЕ решено

Полная карта физических страниц/таблиц нуждается в достоверных координатах от Data Platform (в текущем `AnalyzedDocument.evidence_chunks` гарантированы только смещения нормализованного текста). Ведомственный XML и таблицы 223-ФЗ / B2B потребуют собственных удостоверяемых структурных парсеров и правил версий; нельзя выдавать им схему 44-ФЗ. Общая семантическая проверка произвольных текстовых утверждений, отрицаний и исключений по всем отраслям ещё требует самостоятельного verifier и размеченного людьми эталонного набора, а не лишь числовой проверки и нескольких high-precision отрицательных правил. Нельзя объявлять точность без экспертного human-gold на практике.

**Запреты неизменны:** без слияния PR, production, действий на ЭТП, подписи, платёжных операций и контакта с заказчиком. Watchdog остаётся выключенным; APR-03B Owner/legal/current-EIS acceptance открыта.


### Дополнительная граница доверия к физической странице

Регрессионная ревизия устранена после проверки риска самозаявленного `extraction_attested=true`. Даже если вызывающий код передал «PDF, страница 17», этот аргумент **не принимается** сам по себе. Для выдачи `EXPLICIT_SOURCE_MAPPING_REVIEW` необходимы одновременно:

1. заранее принятый документ с ожидаемым *внешним* `raw_sha256` (`receipt_status=MATCHED_DECLARED_DIGEST`), а не только SHA, вычисленным нами;
2. карта конкретного `[char_start:char_end]` c соответствием SHA исходных байтов и нормализованного текста;
3. точное совпадение карты с отдельно зарегистрированным `research.physical_span_maps`, включая аттестованный producer `data_platform_original_coordinate_map_v1`;
4. полное попадание цитаты в диапазон карты и допустимый тип локатора.

Так как текущий Data Platform не предоставляет удостоверяемое соответствие нормализованного текста физическим страницам и ячейкам, реальные отчёты правильно выводят `PAGE_OR_CELL_NOT_ATTESTED` и не отображают предложенные моделью физические страницы. Синтетический тест демонстрирует будущий контракт только при наличии отдельного raw SHA receipt и заранее зарегистрированной координатной карты; он не означает, что эта карта реализована для всех PDF/DOCX/XLSX.
