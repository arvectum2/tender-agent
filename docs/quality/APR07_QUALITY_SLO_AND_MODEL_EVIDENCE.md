# APR-07 — Product Quality/SLO и безопасный мост к Data Platform

**Состояние на 09.10.2026:** первый воспроизводимый технический срез готов. Это НЕ полная приёмка SLO, НЕ человеческая truth-разметка и НЕ разрешение на замену моделей. Ветки APR-03 (реальный VPS) и APR-06 (коммерческая приёмка) сохраняют собственные блокеры.

## Источник и воспроизведение

Первичная ведомость: `docs/quality/APR07_MEASURED_SNAPSHOT_2026-10-09.json`. SHA-256 самого содержимого рассчитывается канонически и записывается в поле `snapshot_sha256`. Внутри — хеши каждого отдельного входного JSON, а не копии закрытой закупочной документации или секретов.

Входы из нашего репозитория: `apr06_real_probe_receipts_2026-10-09.json`, `apr06_machine_prefill_2026-10-09.json`, `apr06_independent_gpt6_audit_2026-10-09.json`. Время обработки — старый read-only журнал Mac mini `/tmp/apr06_real_analysis_20261009.jsonl`. Код требует совпадения конкретных run_id: нельзя подменить одну закупку другой или добавить фиктивное человеческое решение.

Вход Data Platform: **только уже существующие результаты** из `/Volumes/ArvectumSSD/Arvectum/repos/data-platform/benchmarks/results/model_refresh_2026-10-09/`. Читаются семь JSON-файлов с измерениями, проверяются общие идентификаторы корпуса embedding/reasoning, импортируются ограниченные числовые показатели и SHA-256 каждого файла. Ни веса моделей, ни Hugging Face, ни Ollama, ни llama.cpp, ни API провайдеров этим кодом не вызываются. Продолжающиеся в отдельном процессе загрузки российских моделей Data Platform не пересекаются с APR-07.

Команда на Mac mini (однократный новый путь вывода; существующий снимок защищён от перезаписи):

```bash
cd /Volumes/ArvectumSSD/Arvectum/repos/tender-agent
uv run python scripts/quality/apr07_snapshot.py \
  --dp-result-dir /Volumes/ArvectumSSD/Arvectum/repos/data-platform/benchmarks/results/model_refresh_2026-10-09 \
  --analysis-log /tmp/apr06_real_analysis_20261009.jsonl \
  --output /tmp/apr07-quality-resnapshot.json
```

Для локальной эксплуатации уже существует `GET /api/ops/observability` (очередь, ошибки документов, ingest, backup/storage). Не создавать второй контур мониторинга; он отделён от исторического сравнительного среза.

**Отсутствуют данные для статистически корректного вывода:** верифицированная человеком точность фактов и цитат, точный OCR fallback по страницам, фактическая доля неподдерживаемых форматов среди всех полученных документов, воспроизводимая погрешность unknown, human override, полная end-to-end latency, устойчивые rolling SLO, подтверждённые ошибки GO/NO_GO. В снимке они `NOT_MEASURED`, не нулевые и не зелёные.

Раздел 223-ФЗ нельзя смешивать с 44-ФЗ в одном знаменателе: в предыдущей read-only пробе только для 4/8 закупок найдены официальные ссылки; ещё 4 требуют независимого разрешения неоднозначной редакции. Доступные документы также не прошли проверку полноты. Метрики 223-ФЗ здесь отдельно не утверждаются.

## Результаты Data Platform (приписываются только своим наборам)

Три варианта Qwen3 Embedding сравнивались на **45 страницах сайта Arvectum и 12 запросах Search Console**, а не на 20–30 закупочных документах. Top-1: 0.6B Q8 — **0,583**, 4B Q8 — **0,667**, 8B Q4 — **0,583**. Нельзя заключать об их качестве для закупочных форм и юридических текстов. Разные размерности и квантование: индексы для будущей проверки отдельные.

Два публичных отсканированных документа в Data Platform OCR smoke: Tesseract rus/eng mean CER **0,2140**; Qwen3-VL-4B mean CER **0,1545** (со значительно большей задержкой). Слишком мало образцов для решения о продакшене или о структуре таблиц.

Qwen3.5-4B и 9B прошли **5/5** коротких автоматических проверок требуемых строк/цитат и abstention. Это не независимая проверка всех утверждений и не full Gemma faithfulness benchmark. Результаты reranker сопоставляются только на своём ограниченном top-five. Полный первичный отчёт остаётся в `data-platform/docs/MODEL_REFRESH_QUALITY_2026-10-09.md`. Текущее рабочее семейство моделей и настройки не менялись.

## Proposed SLO — не утверждены владельцем

До запуска реального платного пилота нужны отдельные базовые окна наблюдения, например 7 суток и минимум 100 однотипных случаев с достаточным покрытием. Предложения для согласования: document acquisition ≥95%, пригодность к анализу ≥90% для поддерживаемых типов, p95 end-to-end ingestion-to-report ≤120 с (с отдельной метрикой времени до решения человека), подтверждённая достоверность важных фактов/цитат ≥98%, ноль подтверждённых опасных ложных GO; доля неизвестных должна определяться по независимой полноте обязательных фактов. Это **целевые гипотезы**, а не результат текущего измерения. Без утверждения определения выборки и owner-sign-off SLO НЕ принимаются.

## Кандидатный benchmark-корпус для русскоязычных закупок

Сформирован отдельный `docs/quality/APR07_PROCUREMENT_SOURCE_ROSTER_2026-10-09.json`:
**9/9** существующих аналитических run привязаны к реальным байтам извещений и
контрактных/технических приложений по `file_id`, SHA-256 и последней известной
версии XML. Проверены несовпадения контрольных сумм, дубли источников и чужие run_id.

Это исключительно **реестр входов для будущей независимой разметки**:
`AI_CURATED_SILVER_NOT_HUMAN_GOLD`, `verified_answer_labels=null`,
`attachment_revision_binding_verified=false`. Он не содержит SUT-решений
как эталонных ответов и не разрешает заменить действующую модель. Источники
обязательно сверяются заново с ЕИС и проверяются человеком перед freeze.

## Дальнейшая очерёдность

1. Data Platform продолжает отдельное приобретение и бенчмаркинг российских моделей, Tender Agent ничего не скачивает и не запускает повторно.
2. APR-06 сохраняет требование 20–30 подтверждённых закупок, настоящих решений человека и проверки привязки ТЗ к редакциям. Его GPT-6-аудит — AI-only.
3. Сформировать независимую **замороженную русскоязычную procurement gold** выборку: минимум реальные 44-ФЗ, 223-ФЗ, разные редакции, многостраничные PDF/DOCX/XML, сканы, таблицы, похожие по смыслу, но разные по требованиям, вопросы с недостаточными сведениями. Разметить ссылки на реальные байты/страницы, поля, актуальную редакцию и случаи абстиненции.
4. Применять к очередному результату Data Platform **тот же** замороженный набор без утечки SUT-ответов в эталон. Только после владельческого решения предлагать promotion модели/нового OCR.
5. Ввести непрерывный tenant-safe SLO мониторинг по настоящим завершённым событиям, используя существующий `ops_observability`, и проверять rolling окна уже после запуска пилота.
