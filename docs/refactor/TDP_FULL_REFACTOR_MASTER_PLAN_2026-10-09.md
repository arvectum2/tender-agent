# Tender Agent + Data Platform — полный поэтапный рефакторинг

Дата: 09.10.2026. Каноническая задача: TDP-REFACTOR-20261009. Репозитории: arvectum2/tender-agent и arvectum2/data-platform. Этот документ задаёт программу до полной приёмки, не выдаёт первый этап за завершение всех работ.

## Установленное состояние

- В Tender Agent — 804 Python-файла, 50 файлов operator-модуля, включая upload_service_legacy.py (5924 строки) и report_model_legacy.py (414 строк). Это слои обратной совместимости, а не доказательство, что всё содержимое продублировано.
- В Data Platform — 158 Python-файлов; пакет 0.6.0, consumer contract 1.0, а Tender Agent использует consumer Python SDK 0.3.0. AST-аудит не выявил прямых импортов реализации платформы внутрь продукта или продуктовых модулей внутрь платформы.
- На Mac mini Data Platform успешно отвечала на /health по порту 8094 (версия 0.6.0), Gemma была видна на порту 8081. Но в тестовом Tender Agent LLM provider = stub: доступность модели и Data Platform не означает запуск LLM-анализа.
- Реальная закупка 0372200172326000015: шесть оригинальных документов, в метаданных подтверждённый предмет из XML, срок и НМЦК; в старом разделе отчёта вместо предмета «Раздел 1. Общие требования». Это регрессия приоритета проверенного источника. Остальные UNKNOWN нельзя произвольно заменять неподтверждёнными фактами.
- Data Platform возвращает resource_id, document_id, canonical_uri, chunk_id, диапазоны исходного текста и metadata. Старый адаптер Tender Agent отбрасывал часть этих идентификаторов, ухудшая трассировку.
- Приватный preview уже имел инцидент рассинхронизации Docker-образа и исходников, исправленный в PR #260. Этот контроль версий обязателен и при последующих релизах.

| Документы, OCR/VLM, извлечение, чанки, resource/document/chunk ID, эмбеддинги, pgvector/FTS, поиск | Data Platform |

Не переносить законодательство и решение GO/NO-GO в универсальную Data Platform. Не развивать параллельные OCR/RAG/LLM/индексы внутри Tender Agent.

## Программа и Definition of Done

**R0 — инвентаризация:** канонические checkpoint в обоих репозиториях, скрипт AST-аудита, карта модулей, baseline тестов, договорённость по контрактам и заморозка источников. Никакого удаления кода по одному факту большого LOC.

**R1 — источник → факт → отчёт:** сохранять source IDs/offsets Data Platform; подтверждённые XML-сведения (предмет, НМЦК, срок) проходят через сохранённые метаданные, шаги, JSON/HTML/PDF/DOCX без подмены эвристикой. Подтверждать ссылки на оригинальный файл и XML-локатор. Конфликтующие и несуществующие сведения остаются UNKNOWN. Режим fallback должен быть прямо указан.

**R2 — DP-контракты:** строгая валидация offset/ID, без обратных или отрицательных диапазонов; сквозная совместимость SDK 0.3.0 / контракт 1.0; тесты PDF/DOCX/XLS/TXT на русском, OCR/VLM, индексов и безопасности данных.

**R3 — разделение монолита:** по одному изолированному изменению выделять из upload_service_legacy.py приём и storage, бизнес-нормализацию, контекст, риски/экономику, выходные модели, отчёт и презентацию. Зависимости и обратные импорты проверять AST-тестами. Совместимость старых API сохранять до зелёных frozen-проверок; потом убирать только доказанно неиспользуемый код.

**R4 — один runtime:** явный вызов/отказ модели и причина, версия SDK/сервиса, модель и латентность; никакой подмены fallback полноценным LLM. Source-locked Docker, авторизация и rollback. Русские модели менять только после замороженного бенчмарка.

**R5 — продуктовая приёмка:** реальные сквозные закупки 44-ФЗ/223-ФЗ и frozen набор APR-06 (не менее 20–30, при наличии корпуса), ложные UNKNOWN, верность цитат, пропущенные блокеры, безопасность, PDF/DOCX, проверка человека. Полные тесты и exact-head CI двух репозиториев, частный Mac mini E2E, визуальная проверка владельца.

## Запреты и continuity

Не менять неизменяемые эталоны R7/замороженные результаты ради зелёных тестов. Не менять ПДн/tenant границы, не делать массовую миграцию БД без rollback. Не подавать закупки, не подписывать документы, не принимать юридических/коммерческих решений, не публиковать публичный сервис. Исходный пилот на 18082 не трогать. Watchdog Tender Agent ранее был отключён по указанию владельца: не включать и не дублировать без нового разрешения.

Команда продолжения: прочитать checkpoint в обеих репозиториях и возобновить первый непроверенный этап. Status completed только после R0–R5 и Owner gate.
