# Договоры 223-ФЗ: границы доказательств открытого реестра

Правила ведения реестра договоров по постановлению Правительства РФ от 31.10.2014 № 1132 определяют объём публикуемых сведений. Подпункт «д» пункта 2 включает предмет, цену и срок договора; подпункт «е» — сведения о поставщике; подпункт «м» — копию договора, подписанную квалифицированной электронной подписью. Пункт 19 исключает сведения подпунктов «е» и «м» из публикации в открытой ЕИС (в числе других исключений).

Источники: https://www.consultant.ru/document/cons_doc_LAW_170528/93e5e111cbfb5c03e38e2cf2f18719c447302cfd/ ; редакция от 30.09.2026: https://www.kontur-extern.ru/info/normativ/document/1/508614-postanovlenie-pravitelstva-rf-ot-31-10-2014-n-1132?view=mobile-app

Следствия для Tender Agent:

- Поля официального contract-register XML о цене/предмете/дате допустимо атрибутировать публичной реестровой записи договора. Они не равны данным об оплате или криптографически проверенному подписанному экземпляру.
- Отсутствие поставщика в публичном XML ожидаемо по правилам раскрытия. Это не «нет поставщика» и не ошибка Data Platform.
- Кандидата на заключение договора, победителя конкурса и юридически установленного поставщика заключённого договора различаем. Протокол комиссии, карточки первичной ЭТП и собственные раскрытия заказчика проверяются отдельно.
- Отсутствие открытой подписанной копии не является доказательством того, что договор не заключён.
- Сумма комплексного EPC/ПИР договора не равна объёму поставки отдельного оборудования PQ.
- XML доказательства: SHA-256 источника, SHA-256 XML, номер закупки, лот, реестровый номер, код валюты, цена и ревизии. Дубли редакций не суммировать.
- OCR без визуальной проверки не используется для подтверждённой личности победителя.

Реестровые записи из локального малого поднабора не следует экстраполировать на рынок 2024–2026.
