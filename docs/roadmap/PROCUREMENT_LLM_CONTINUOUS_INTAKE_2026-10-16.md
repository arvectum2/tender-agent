# Procurement LLM: операционный захват ручных разборов и завершённых прогонов

**16.10.2026 — внедряется в отдельном дочернем PR от #451. Модель не создаём.**

## Контур данных

Остаются единственные источники: действующая база PostgreSQL `arvectum` (в контейнере `arvectum-postgres`) и уже существующий `/Volumes/ArvectumSSD/Arvectum/data/tenders/` для оригиналов. Таблица `procurement_learning_observations` имеет Alembic 107. Записи `candidate_unreviewed`, не `train_ready` и не `legal_gold`.

## Что теперь поддерживает код

- **Завершённый customer_pilot run**: `complete_run` сохраняет candidate в той же транзакции, что и `run.status=completed`, причём только после успешной canonical source binding. `customer_id` поступает из текущего customer pilot, scope — `tenant`. Идентификатор observation детерминирован от `run.id`; повторное completion не дублирует запись; исходные файлы не копируются.
- **Исторический / RAG run**: существующий `record_analysis_run` также может сохранять candidate в этой БД.
- Для обоих путей необходим **`TENDER_LEARNING_CAPTURE_ENABLED=1`** в реально развёрнутом сервисе, и предварительно установленная миграция 107. При выключенном флаге рабочие пути сохранения не меняются. Не включать флаг в старых runtime-образах без этой реализации.
- **Ручной ChatGPT-разбор**: оператор/агент при наличии разрешённого локального доступа отправляет **структурированный JSON** прямо в `python -m scripts.procurement_llm.import_candidates --manual-stdin --apply --confirm-database arvectum`. Без `--apply` идёт только валидация JSON, без обращения к базе; вход через стандартный ввод не создаёт отдельного файла.
- CLI принимает 1–1000 наблюдений (`manual-candidate-import-v1`) за раз; stdin максимум 64 KiB. Отклоняет `protected_blind`, `blind_holdout`, неподтверждённый `submitted`, `legal_gold`, `signed_human_gold`, сырые чаты/секреты; устаревшее изменение того же `event_id` конфликтует, а идентичная запись идемпотентна. В БД сохраняем **метаданные, ссылки на оригиналы и технические выводы**, но не весь чат/секреты/дубликаты документов.

## Регламент для ChatGPT-агента

Если проводится новый глубокий ручной анализ закупки по пользовательскому запросу или обсуждается реальная подача/результат:

1. Определи `procurement_ref` (реестровый номер или platform-qualified ID) и уникальный стабильный `event_id` для конкретного анализа/редакции. Укажи дату/время, официальный URL или локальный SHA подтверждённого оригинала, версию документа, вердикт/риски/вопросы, пробелы в доказательствах.
2. Укажи `participation`: `submitted` **только при проверенной квитанции/протоколе или явно помеченном `owner_reported`**; иначе `considered` / `reviewed_only` / `unknown`. Не делать вывод о допуске/победе из факта подачи.
3. Подготовь краткий структурированный JSON без текстов переписки, личных данных, учётных сведений или закрытого blind evaluation. Передай через приватный stdin CLI; используй безопасно настроенный `AI_CORP_DATABASE_URL` той же базы (не печатай URL с паролем). Сначала dry-run, затем `--apply --confirm-database arvectum` только при разрешённом локальном доступе.
4. Проверь `inserted` либо `existing`. Если запись уже есть, не редактируй её: новое фактическое исправление оформляется новым event ID с ссылкой на предыдущее.
5. Когда подключение недоступно, **прямо сообщи, что не сохранил запись**, и оставь явную ожидающую задачу на intake. Никогда не утверждай, что все новые чаты автоматически попадают в PostgreSQL только потому, что этот файл существует.

Пример **обезличенной формы** (значения заменить реальными, не вставлять личные данные):
```json
{
  "event_id": "manual-20261016-example-0001",
  "procurement_ref": "0000000000000000000",
  "participation": "reviewed_only",
  "review_state": "unverified_chat_recall",
  "source_links": [],
  "review_summary": "Исходные документы ещё требуют проверки",
  "model_gold": false,
  "protected_blind": false
}
```

Пример invocation (с секретом подключения, безопасно настроенным **в среде**, не в самой команде):
```bash
python -m scripts.procurement_llm.import_candidates --manual-stdin < /PRIVATE/path/review.json
python -m scripts.procurement_llm.import_candidates --manual-stdin --apply --confirm-database arvectum < /PRIVATE/path/review.json
```

Использование `stdin` позволяет передавать JSON потоком **без промежуточного файла**. Показанный путь к файлу — только для примера.

## Существующие ограничения

Ни ChatGPT, ни репозиторий **не имеют глобальной подписки на все существующие и будущие разговоры**, включая отдельный проект «Закупки с моим участием». Нужен реальный вызов intake на каждом разборе; для неподключённых чатов это остаётся открытым интеграционным шагом. История прежних чатов восстановлена только частично; не заявлять, что все старые разговоры уже импортированы. Никакой отдельной БД, публичного неаутентифицированного маршрута, обучения модели, автоматической передачи данных сторонним заказчикам или изменения ЭТП не добавляется.
