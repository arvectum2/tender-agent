# PRICE-01 — офлайн-приём проверенных контрактных источников

Статус: проверен на синтетических XML, не подключён к рабочему каталогу.
Это отдельный слой подготовки доказательств, не API загрузки пользовательских цен.

## Контракт формата

- Манифест JSON версии 1, не более 256 КиБ; от 1 до 20 различных процедур.
- Оригиналы XML UTF-8, до 2 МиБ на файл, имя файла: SHA-256 исходных байтов + .xml.
- Доверенный рецензент заранее закрепляет SHA-256 именно проверенного манифеста. Самостоятельно вычисленный SHA непроверенного входа не подтверждает качество источника.
- Для каждого контракта рецензент указывает точный оригинальный адрес, SHA, номер закупки и контракта, дату подписания, цену в RUB, точное договорное количество, единицу, полный состав, налоговые и ценовые условия.
- Каждый факт связан с отдельным XML-листом: path (индексы дочерних узлов, начиная с нуля от корня), tag (точное имя, включая namespace при наличии), text (полный текст листа). Семантику поля проверяет рецензент: тег сам по себе не устанавливает юридический статус.
- Явные подтверждения подписания контракта, покрытия полной цены указанным объёмом и сопоставимости выбранной группы обязательны; различный полный состав, единица или условия цены не допускаются.
- Расчёт на Decimal, шесть десятичных знаков, ROUND_HALF_UP. На одну процедуру — один контракт; диапазон только при двух и более разных процедурах, медиана по неокруглённым удельным ценам.
- Не смешивать цены допущенных заявок, НМЦК, подписанные цены и фактическую оплату. Количество по контракту не означает фактическое исполнение, срок не означает трудозатраты, наблюдение не является текущей рыночной ставкой.

## Запуск

```sh
python -m scripts.price01.intake_reviewed_contracts \
  --manifest /private/review.json \
  --reviewed-sha256 <trusted_review_manifest_sha256> \
  --originals /private/originals
```

CLI читает локальные файлы, отклоняет symlink конечного файла, запрещает DTD/внешние сущности, ограничивает объём и структуру XML. Вывод — JSON с контрольной суммой receipt_sha256; без записи в БД. Хранить оригиналы/манифест отдельно, не публиковать персональные данные. Доступ к доверенному источнику и правовой статус подписания не проверяются автоматически: флаги независимой проверки подлинности, ЭП, исполнения и фактического количества остаются false.

## Граница этапа

Реальных новых оригиналов подписанных контрактов пока нет. Текущий шестипроцедурный архив и его клиентские SHA не изменены. Следующий этап — серверный reviewed-published receipt registry с закреплёнными доверенными манифестами и безопасной версионной публикацией; новые реальные источники должны пройти отдельную проверку. Не подключать произвольные локальные файлы к публичному каталогу.
