# Procurement LLM — приём внешних исследований ChatGPT в единую PostgreSQL

**18.10.2026, ООО «Арвектум».** Второй этап после подтверждённого импорта 31 исторического наблюдения и внутреннего захвата веб-страниц в Tender Agent. Задача: обеспечить защищённый, воспроизводимый **явный** импорт каждого следующего разбора, выполненного в ChatGPT вне запущенного Tender Agent, в уже существующую таблицу procurement_learning_observations PostgreSQL arvectum.

## Новый рабочий маршрут

Скрипт scripts/procurement_llm/capture_external_research.py принимает JSON-манифест строго версии external_chatgpt_procurement_research_v1, который содержит:

- закупку, площадку, URL первичного источника, дату и модель, проводившую разбор;
- отдельно source proof: **ORIGINAL_SHA_VERIFIED** — локальный оригинал в защищённом каталоге на ArvectumSSD и совпадающий SHA256 его фактических байтов; либо **PUBLIC_URL_UNVERIFIED** — лишь исходная публичная URL без притворства, что оригинал проверен;
- путь к отдельному самостоятельному санитизированному аналитическому файлу MD/TXT (это *не* полный чат), с режимом доступа 0600 и ограничением 250 KB; SHA файла сверяется и кладётся в метаданные;
- конкретную provenance версию, неизменяемый event ID на комбинации source ref / URL SHA / original source SHA / анализа SHA. Replay того же отчёта идемпотентен; новая версия отчёта append-only.

В существующую SQL таблицу записываются **только метаданные**, SHA и приватный путь к полному отдельному отчёту, но **не полный HTML, не сам отчёт, не transcript чата и не фактическая юридическая истина**. Все записи имеют owner_internal/candidate_unreviewed; отсутствие настоящего оригинала явно ведёт к unverified_chat_recall. Никакого human/legal/model gold, автоматической подписи/заявки, обучения весов модели или tenant scope.

Разрешённые исходные площадки: EIS (официальный zakupki.gov.ru и только публичный regNumber), Workspace, B2B-Center или иной публичный HTTPS-домен без query/secret. Валидация не доверяет пользовательскому URL: запрещает пароль в ссылке, IP вместо DNS, localhost/internal, query токены, перепутанный номер, небезопасные/внешние файлы, symlink, world-readable/private несоответствие, неправильный SHA и неизвестные поля.

Приватная директория /Volumes/ArvectumSSD/Arvectum/private/tender-agent/analysis-artifacts создана с доступом 0700. Исходники и отдельные отчёты остаются **только на ArvectumSSD**, вне Git. Манифест также приватный, режим 0600, в существующей структуре /Volumes/ArvectumSSD/Arvectum/private/tender-agent/.

### Порядок применения в следующих рабочих чатах

1. В момент каждого внешнего разбора закупки получить первоисточник, указать, есть ли реально SHA-сверенный локальный оригинал. Без оригинала честно поставить PUBLIC_URL_UNVERIFIED.
2. Сохранить отдельный самостоятельный аналитический отчёт в приватном каталоге, 0600, **без сырого чата, личных секретов и несанкционированной внешней передачи**; создать приватный JSON-манифест.
3. Прогнать dry-run штатного валидатора: python -m scripts.procurement_llm.capture_external_research --manifest PRIVATE_MANIFEST. Выводит observation SHA, не обращается к БД.
4. При действующем Owner-разрешении обязательного сохранения выполнить python -m scripts.procurement_llm.capture_external_research --manifest PRIVATE_MANIFEST --apply --confirm-database arvectum в авторизованном Mac mini окружении, со ссылкой на **существующий** PostgreSQL. Получить машинный ответ inserted=1 либо existing=1, отдельно проверить read-only строку.
5. Только когда запись реально присутствует в рабочем PostgreSQL, считать соответствующий **конкретный** ChatGPT разбор сохранённым. Не утверждать, что произвольные старые чаты или веб-поиски сохраняются сами.
6. Впоследствии, **после формальной приёмки продукта**, создавать отдельную реальную независимую рецензию Tender Agent на точно те же SHA исходников, фиксировать diff и человеческие исправления по контракту PR489. Слепую evaluation-выборку не включать в обучение.

## Тесты и ограничения

28 новых unit/security/metadata/SQLite transaction тестов PASS; 740 широких Tender Research / Procurement Learning / Customer Pilot тестов PASS, 2 SKIP, Ruff PASS. SQLite применяется **исключительно в тестовой фикстуре**; настоящая запись CLI настроена через прежний guarded _engine_url, который разрешает только существующую PostgreSQL arvectum.

**Ограничение:** это защищённый *явный* CLI для будущего вызова агентом по завершении каждого внешнего исследования. Он не имеет сетевого webhook, доступа к внутреннему состоянию ChatGPT, не читает другие чаты, не обеспечивает сквозной auto-capture без фактического обращения агента. Дальнейший шаг — автономный интеграционный collector с разрешёнными соединениями для каждого провайдера, End-to-End тестами и контролем пропусков.

**В этом инженерном этапе новые реальные закупки не разбирались и production DB не мутировалась:** предыдущие 108 записей остаются прежними. Обязательное сохранение уже одобрено Owner и применяется при появлении настоящего следующего разбора, не при имитации тестовых данных.
