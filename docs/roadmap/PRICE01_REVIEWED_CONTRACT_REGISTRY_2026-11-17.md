# PRICE-01 — версионный реестр проверенных контрактов

Начальная версия 0001 — пустая. Никакие синтетические контракты не опубликованы.

## Публикация новой версии

1. Отдельно собрать и проверить оригиналы и манифест по PRICE01_REVIEWED_CONTRACT_INTAKE_2026-11-17.md. SHA манифеста должен поступить из доверенной проверки, а не из непроверенного клиентского запроса.
2. Получить JSON receipt через офлайн CLI intake_reviewed_contracts. Проверить разрешённость публикации всех полей, включая текст заметки в хранимом receipt; не помещать приватные оригиналы, персональные данные и секреты в репозиторий.
3. Сохранить проверенный receipt в docs/roadmap/price01_contract_registry/receipts/<SHA-256 байтов>.json. Запись релиза содержит review_id, reviewed_manifest_sha256, receipt_file_sha256, receipt_sha256 и явно проверенную публичную метку состава работ.
4. Создать следующий releases/NNNN.json: schema reviewed_contract_registry_release_v1, version, previous_release_sha256, published_on, entries (полный состав действующего набора). Добавить SHA-256 точных байтов релиза в конец RELEASE_PINS в модуле reviewed_contract_registry.py. Старые релизы и receipts сохранять неизменными. Изменение опубликованной группы требует новой записи review_id. Исключение группы выполняется только новой версией релиза.
5. Проверить load_registry(), регрессию и независимое ревью изменения. Публикация — отдельное решение, не результат одного вычисления SHA.

## Границы

API GET /api/saas/company-portfolio/cases/{case_id}/reviewed-contract-registry. Требуются три default-off флага: price_scenarios, historical_comparables, reviewed_contract_registry. Доступ owner/admin/analyst и собственная карточка, юридические условия должны быть приняты. API возвращает действующие группы и метаданные цепочки, но не исходные XML, приватный манифест, рецензента, ссылку на файл или заметку проверки. Для каждого запроса проверяется цепочка закреплённых релизов, точные SHA файлов, связь с проверенным манифестом, арифметика и уникальность данных. Группы не объединяются; эквивалентность целевой закупке не утверждается. Нет рекомендаций, автоподстановки в смету или проверки фактического исполнения и подлинности ЭП. До 32 версий, 20 действующих групп на релиз, 64 уникальных исторических группы. Повреждение любой закреплённой версии или записи блокирует выдачу HTTP 503. Механизм доверия основан на проверке кода и исходных манифестов, а не на независимой криптографической подписи рецензента.

Существующий шестипроцедурный архив и фиксированные клиентские SHA не менялись. Web/iOS новый endpoint ещё не используют. Реальное пополнение источников отдельной исследовательской задачей; промышленная активация не проводилась.
