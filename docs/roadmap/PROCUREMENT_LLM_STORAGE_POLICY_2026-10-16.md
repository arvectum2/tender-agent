**Owner directive, 2026-10-16.** Начинаем собирать кандидатов для будущего дообучения уже сейчас. **Обучение модели, её веса, отдельный ML-сервис и новый репозиторий в этом этапе НЕ создаём.** Данные сохраняются в существующей инфраструктуре Tender Agent, не в отдельной базе «Procurement LLM».

**Зафиксированное исходное состояние (read-only audit):** PostgreSQL `arvectum`: 20 записей `procurement_tenders`, 95 `procurement_tender_documents`, 45 `tender_analysis_runs`, один snapshot протокола и 55 предложений в `tender_bid_result_offers`. SSD `data/tenders/eis`: 15 папок закупок / 142 файла, `data/tenders/results` содержит протокол по **0158300034526000388 (Аксай)**; ранее импортированы 55 ставок, в том числе «Арвектум» 119 000 ₽ / 38-е место, победитель 28 400 ₽. Пример первого полного комплекта: **0372200172326000015 (Музей хлеба)** — оригиналы `application.docx`, `contract.doc`, `control.pdf`, `price.xls`, `tz.docx` и тексты в `data/tenders/eis/...`.

Нельзя путать `tender_db`, `ai_corporation` на host PostgreSQL с **реально заполненной** Docker PostgreSQL `arvectum`. Отдельная Data Platform DB также не становится procurement training truth.

## Правило обязательного пополнения

После **каждого** нового ручного глубокого разбора, **каждого** Tender Agent / Gemma / иной модели прогона, каждой заявки ООО «Арвектум» и появления результатов торгов нужно создавать либо обновлять **связанный набор записей в существующей `arvectum`**, используя имеющиеся entities; дополнять первоисточники только внутри существующего `data/tenders`. Любое дальнейшее расширение схемы — обычная версия Alembic **этой же базы**, с тестами и review, **без создания SQLite, отдельного PostgreSQL, параллельного corpus-v2 или копирования файлов в самостоятельный dataset store**.

На каждое наблюдение фиксировать: реестровый номер или внешний B2B-ID и источник; редакцию извещения; URL официального источника; дату проверки; исходные SHA документов и run_id; модель, промпт/schema/pipeline version, ответы и полученные метрики (ссылки на сохраняемые run artifacts, не их бессистемное копирование); авторство и статус ручной интерпретации; предмет/требования/риски/коммерческие выводы; подтверждённый статус участия (`submitted` / `considered` / `reviewed_only` / `unknown`) и доказательство, если оно есть; исход и протокол, если есть. Один procurement ID может иметь много редакций, прогонов, исправлений и предложений — **никогда не перезаписывать историю**. Дедупликация по (source, procurement ID, редакция / source hash, run ID / event ID) с append-only происхождением.

**Первоначальный backfill** (выполнен, см. [протокол](PROCUREMENT_LLM_BACKFILL_2026-10-16.md)):  без повторных скачиваний и без запуска модели проиндексировать все сохранённые 20 исторических DEVELOPMENT E2E Gemma4 закупок (210 source SHA, 80 модельных вызовов, 60 EIS XML-цитат); все известные подробные ручные разборы, включая заявки Музея хлеба, Аксая и прочих закупок с участием Owner; новые случаи добавлять аналогично. Записи, существующие в `procurement_tenders` / `tender_analysis_runs`, **не создавать заново**. Сначала сверить номер+хеш+ID, затем создать недостающие ссылки или версионированные события в той же БД. Запись о подаче заявки без первичного протокола остаётся `owner_reported`, а не `verified`; цена/принятое решение/результат без первоисточника остаются `unknown`. Локальное приложение не имеет доступа ко всей истории чатов автоматически: будущие разборы из ChatGPT надо передавать в штатный intake через явный инструмент/коннектор; **для `record_analysis_run` реализован opt-in hook, но все чаты ChatGPT и другие runtime-пайплайны пока не захватываются автоматически**.

## Границы качества, прав и безопасности

- **Не экспортировать оригиналы, персональные и коммерчески закрытые файлы, историю чатов, токены, подписи или полные ответы моделей в GitHub.** Только код, миграции, безопасную документацию и агрегированные неидентифицирующие метрики. Документы могут использоваться для обучения лишь после проверки разрешений/прав и редактирования чувствительной информации.
- Чётко разделять **`source_verified`**, **`AI_generated`**, **`owner_reported`**, **`human_reviewed`**, **`legal_gold`**. Достоверность SHA и правильность интерпретации — разные проверки. Ни одна рекомендация ИИ не становится юридическим gold автоматически.
- **15 защищённых blind R4 кейсов / 73 оригинала** и любой будущий закрытый оценочный набор **не попадут в обучающий набор или доступ модели при создании train examples**. DEV corpus с 20 ранее раскрытыми прогонaми не использовать как новый независимый blind benchmark. Сплиты сначала определить на уровне закупки (не случайных документов), чтобы не было утечки между train и eval.
- Разрешён только read-only осмотр без особого разрешения; любое изменение live PostgreSQL, реальных заявок/ЭТП, production, юридических или финансовых последствий — отдельное разрешение и соответствующая миграция/проверка. Схема не должна обходить tenant/customer ACL и Product/DP authority boundaries.
- **Подготовка обучающих пар / LoRA / QLoRA / модельная промоция** — отдельный будущий этап Arvectum Procurement LLM, не часть включённого сейчас сбора данных.

## Исправление лишнего экспериментального SQLite

В предыдущем проходе был **создан лишний** кандидатный SQLite в `/Volumes/ArvectumSSD/Arvectum/private/procurement-llm/corpus-v1/candidate-registry.sqlite3`. Там **29 экспериментальных метаданных-наблюдений**: 20 раскрытых development-прогонов и 9 вручную восстановленных карточек; 27 уникальных идентификаторов. **Этот SQLite НЕ является и не должен становиться канонической базой**, никаких новых записей туда не добавлять, библиотеку `scripts/procurement_llm/corpus_registry.py` с SQLite **не вносить в репозиторий**. Перенос `29/29` и индексирование 45 существовавших анализов завершены, итого в `arvectum` 74 кандидата. Сохранить исходную SQLite как frozen резервный файл, не удалять до отдельного финального контроля. Ни один из 29 метаданных-черновиков не считается train-ready / legal gold.

**Definition of Done следующего отдельного code этапа:** (1) canonical DB migration + отражение исходного source/run/correction lineage внутри той же `arvectum`; (2) backfill 20/20 + 9/9 metadata без дублей, с точными ссылками на оригиналы и сохранением неизвестных полей; (3) единый idempotent capture hook для новых manual reviews и automated runs; (4) тесты на ACL, защиту holdout, дефекты ссылок, повторный импорт и отказ на недоказанные факты; (5) приватный бэкап и проверки до какой-либо очистки временных файлов; (6) никакого обучения модели сейчас.
