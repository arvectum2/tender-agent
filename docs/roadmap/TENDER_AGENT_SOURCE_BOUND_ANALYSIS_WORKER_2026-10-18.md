# Tender Agent — воркер настоящего анализа по проверенному оригиналу

**18.10.2026, ООО «Арвектум».** Дочерний этап TA-SOURCE-ANALYSIS-WORKER-20261018 поверх уже завершённого PR #494 (unified discovery/source-first intake; к последней проверке CI 19/19). Реализация review-only, не сливали PR в main и не развёртывали новый backend или launchd.

## Внесённый код

- `scripts/procurement_llm/analysis_queue_worker.py` читает **эту же** PostgreSQL `arvectum.procurement_learning_observations`, восстанавливает последний проверенный original для каждой закупки; ни второй БД, ни новой миграции. Точно проверяет, что файл owner-private `0600` находится под ArvectumSSD/private/tender-agent, не symlink, имеет неизменное имя SHA, реальный SHA-256 байтов совпадает с кандидатом и оригинал не подменён.
- Marketplace HTML-only (Workspace/B2B): **только карточка** не является полным документальным контекстом → `marketplace_html_only_no_prepared_tender_documents`. Нельзя подавать HTML как готовый тендер и генерировать unsupported ответы.
- Официальные ЕИС ZIP: допуск к настоящему `analyze_tender(... use_llm=True, save_report=True, record_history=True)` возможен только когда Тендер Research действительно содержит тот же 19-значный номер, режим 44-ФЗ, **индексированную и архивно привязанную к тому же original SHA** документальную версию, локальные chunks и соответствующую Data Platform коллекцию с ресурсами и embeddings. Placeholder карточки и внешние архивы без подготовки не допускаются.
- Модель должна отвечать на localhost/OpenAI-compatible `/v1/models` именно в указанной конфигурации; запрещены интернет-модель, токен в URL, другой локальный endpoint, и автоматическая подмена недоступной модели. Опциональный явный CLI override `--llm-base-url http://127.0.0.1:11434/v1 --llm-model qwen3:4b` проходит локальную проверку, **не меняет системную конфигурацию**.
- Только фактически сохранённый `TenderAnalysisRun` с `source=source_queue`, `completed`, `used_llm=True`, цитируемыми источниками, ненулевыми LLM вызовами, **каждым разделом completed (без retrieval_only/fallback)** и подлинным файлом отчёта под разрешённой `data/rag/reports` создаёт дополнительную metadata-only кандидатку `ta-ready-analysis:...` с ID конкретного исходного source observation, SHA оригинала, run ID и SHA реального отчёта (новый отчёт приводится к `0600`). Никакого raw отчёта в learning таблице, BID_GO или gold.
- `completed_source_versions` при каждом чтении перепроверяет настоящий сохранённый `TenderAnalysisRun`, модель, статус, SHA отчёта и ссылку на версию оригинала. Поддельная manual event или исторический run с тем же номером **не закрывает очередь**. Изменившаяся source version ставится в очередь снова.
- Исправлен `unified_source_pipeline.recorded_source_refs`: generic `analysis_run` не закрывает конкретную source SHA версию, только подтверждённый completion worker. Шестичасовой `scripts/runtime/run_source_intake.sh` после успешного нового source cycle при отдельном `TENDER_QUEUE_ANALYZE_APPLY=1` может обработать максимум **одну** готовую закупку настоящей моделью; по умолчанию этот флаг `0`, worker не стартует. Никакой установленной launchd-службы, auto-deploy или неограниченной модели.

## Реальная проверка 18.10.2026

- Единая PostgreSQL по-прежнему **119 source/learning observations, 45 прежних TenderAnalysisRun**. Прямой source-ready audit: **10 ожидающих source refs**; из них **7 marketplace HTML-only**, **3 EIS ZIP без TenderResearch tenders**. **0 разрешённых реальных LLM run**, 0 новых записей, 0 gold и 0 BID_GO. `--probe-services` выполнялся только read-only.
- Data Platform HTTP health=200, но пустая или подготовленная только частично коллекция не считается готовой. Настроенный старый LLM endpoint 127.0.0.1:8088 не отвечает; при этом существующий **Ollama** 127.0.0.1:11434/v1/models HTTP200 поддерживает `qwen3:4b`, `gemma4:12b`, `qwen2.5:3b`. Предварительная проверка `qwen3:4b` пройдена. Запросы на генерацию **не отправлялись**, поскольку 0/10 готовы по оригиналам/индексу.
- 20 targeted adversarial tests первоначально PASS, затем добавлены дополнительные проверки строгого связывания индексированных документов и безопасного локального LLM override. Full regression выполняется отдельным сквозным прогоном; приёмо-сдаточный CI — через GitHub PR.
- Не запускали `prepare_tender_for_analysis` на действующей БД: реальный загрузчик 44-ФЗ `RealEisLoader` через `getDocsIP` предоставляет в текущем коде placeholder с URL архива, а не весь source-version-bound комплект скачанных официальных DOCX/PDF; простое создание карточки не решает точного связывания контекста. Подмена поля `owner_attested_original_archive_sha256` без проверки источников запрещена.

## Что осталось сделать до настоящего сквозного анализа

1. В отдельном child-этапе подготовить из ZIP/XML ЕИС и точных ссылок filestore source-bound **полный комплект приложений** (можно переиспользовать `eis_archived_source_integrity` / `extract_notice_attachments`, download binaries SHA) в Tender Research document pipeline и Data Platform, добавить взаимно проверяемый source-manifest. Для Workspace/B2B при наличии исходных ТЗ PDF/DOCX — соответствующие безавторизационные первичные оригиналы, иначе BLOCKED.
2. Только по фактически подготовленным данным запустить **один настоящий** локальный `qwen3:4b` в изолированном owner-approved режиме с сохранением report, model/cited chunks/run/source SHA, сверить SQL before/after. Не объявлять работу сделанной по одним тестовым mocked runs.
3. По подтверждённой технической приёмке отдельно запустить независимые параллельные ChatGPT / Tender Agent анализы одинакового manifest SHA, human adjudication и только после неё рассматривать Procurement LLM fine-tuning.
4. Разрешённое AM-4 слияние stacked PRs, backend/source scheduler install, запуск с `TENDER_QUEUE_ANALYZE_APPLY=1` — **не выполнены**. Существующий Tender Agent Watchdog не дублировать.

**Итог:** реальный source-bound LLM worker интегрирован в review-code, dry-run/адверсариальная проверка работают; 10 текущих источников честно заблокированы до source-bound документальной подготовки. Это не 10 готовых AI-анализов и не незаметное обучение модели.
