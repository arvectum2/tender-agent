## 2. Постоянное правило для всех будущих закупок

Для каждого нового поиска и разбора фиксируются площадка/оригинальный номер, source URL, время, SHA и редакция оригинала, статус проверки актуальности, идентификатор запуска, версия/параметры аналитика, source-grounded выводы и человеко-проверенные исправления, если они впоследствии появятся. Повтор оригинала — идемпотентная запись; новая редакция либо новый анализ — append-only событие, не перезапись истории.

- Существующие канонические пути saved TenderAnalysisRun и завершения customer pilot run уже записывают observation **в одной SQL-транзакции**. В review-коде введён единый learning_capture_enabled: по умолчанию **включено**; явный 0 допускается для изолированных тестов/санкционированного обслуживания, неявное неверное значение вызывает ошибку и не позволяет молча потерять evidence. Требуется установленная миграция 107.
- Новый read-only инструмент scripts/procurement_llm/audit_learning_capture.py --strict выявляет пропущенные записи анализа и неожиданное повышение training status; реальный запуск на 108 наблюдениях: **45/45 saved runs captured, 31 ta-research, 0 missing, 0 unexpected promoted**.
- Поисковые карточки Workspace/B2B-Center из **внешних ChatGPT исследовательских запусков** пока не попадают в БД полностью автоматически: для них имеется безопасный metadata bridge и штатный guarded importer, но отдельный unified Collector/ingest и автоматическая доставка из каждого будущего чата в DB **ещё требуются**. Считать задачу полной раньше проверенного end-to-end нельзя.
- До развертывания review PR код действующего сервиса остаётся предыдущим; backend и единственный Operator Workspace на порту 18082 этим этапом не перезапускались. Не выдавать новый default-on код за уже развернутую настройку.

## 3. После технической приёмки: два независимых разбора

**Условие запуска:** документированная technical acceptance Tender Agent. До её завершения новая система не должна выдумывать два прогонa, делать сопоставление либо запускать ChatGPT API от имени владельца.

1. Зафиксировать одну закупку и один список документальных SHA, один source_manifest_sha256 и одну утверждённую source version. Оба анализа получают **идентичный** оригинальный пакет, не результаты друг друга.
2. Через ChatGPT сделать независимый разбор с реальным run/artifact reference; через Tender Agent выполнить другой независимый разбор и сохранить его run/artifact reference. Оба содержат источник, SHA промпта, модель/версию, время, SHA вывода и цитаты на SHA оригиналов, без публикации приватного raw содержимого в обучающий реестр.
3. Сопоставить поля procedure_status, application_deadline, subject_and_scope, qualification_requirements, technical_requirements, financial_requirements, supplier_eligibility, risks и recommended_next_action. Каждое поле получает **AGREE_NOT_GOLD**, **DISAGREE_REQUIRES_HUMAN_REVIEW** либо **MISSING_IN_ONE_REVIEW**.
4. Даже совпадение двух моделей не является human/legal gold. Приоритет на стороне независимой проверки по первичным документам, исправлениям человека, фиксации авторства, версии и причины отклонения. Не использовать ChatGPT или локальную модель как безусловно правильный эталон.
5. Только после отдельной проверки допускается supervised example в согласованном тренировочном срезе; protected holdout и независимые gold benchmarks остаются отдельно, проверяются права на обработку текстов и область доступа tenant/customer.

Реализован scripts/procurement_llm/dual_review_intake.py: безопасная **offline** проверка структурированного контракта procurement_dual_review_post_acceptance_v1. Она требует accepted + SHA документа приёмки, двух различных reviewer/run/выходных артефактов, одинаковых SHA исходников, строгих ссылок на исходный source list и нормализованных хешей выводов. Формирует **три** candidate_unreviewed события в существующем manual-candidate-import-v1 формате: ChatGPT, Tender Agent и comparison. Не вызывает внешние модели, не создаёт gold, не отправляет ни заявку, ни сообщение. Запись возможно подготовить только в PRIVATE каталог с правами 0600 по явной команде; ни один фиктивный test case не отправлен в рабочую PostgreSQL.
